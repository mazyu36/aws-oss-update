## 概要

このリリースでは、2026-10-12 にローンチされた Lambda WebFunction のための L2 コンストラクト (`WebFunction` / `NetworkConnector`) が追加され、専用バケット・リビジョン・エンドポイント・ネットワーク接続の面倒なワイヤリングを 1 つの L2 でまとめて扱えるようになりました。CloudWatch では `MathExpression` / `SearchExpression` の `visible` プロパティのサポート、`SingleValueWidget` のライブデータ対応、core では `Validations.acknowledge` による警告の文脈スコープ抑止、EKS 1.37 対応、Lambda Python 3.15 ランタイムが追加されています。L1 リソース定義の自動更新に伴って CodeBuild/DAX/EC2 の `Id` 属性が削除される破壊的変更、および `redshift-alpha` のドット区切りテーブル名の扱いに関する破壊的変更にも注意が必要です。

**リリース:** [v2.276.0](https://github.com/aws/aws-cdk/releases/tag/v2.276.0)

## 新機能

### Lambda WebFunction / NetworkConnector L2 コンストラクトの追加 ([#39210](https://github.com/aws/aws-cdk/pull/39210))

**この機能でできること:**
- 2026-10-12 にローンチされた Lambda WebFunction を、L1 (`AWS::Lambda::WebFunction` / `WebFunctionRevision` / `WebFunctionEndpoint`) を自分で組み立てずに 1 つの L2 で扱えるようになりました。依存関係の管理や `FunctionName` の共有、デフォルトロールの作成、`grants.invoke()` などが自動化されます。
- WebFunction はコードを S3 から **Lambda サービスプリンシパル** で起動時に読み込む仕組みのため、Versioning・SSE-S3・サービスプリンシパル向けバケットポリシーが必要です。この要件を満たすための 3 つのコード提供方法 (`WebFunctionCode.fromBucket` / `fromAssetToManagedBucket` / `fromAssetToProvidedBucket`) が用意されています。
- VPC Egress は `lambda.Function` と異なり `NetworkConnector` という別リソースで一元管理され、複数の関数で共有できます。

**使用例:**

```typescript
import * as lambda from 'aws-cdk-lib/aws-lambda';
import * as ec2 from 'aws-cdk-lib/aws-ec2';
import * as s3 from 'aws-cdk-lib/aws-s3';
import * as path from 'path';

// ---- パターン 1: ローカルアセットから CDK 管理の専用バケットへステージング ----
const webFn = new lambda.WebFunction(this, 'WebFn', {
  // コード: ローカルアセットをスタック単位の管理バケットへコピー
  // (Versioning / SSE-S3 / サービスプリンシパルポリシーが自動設定される)
  code: lambda.WebFunctionCode.fromAssetToManagedBucket(path.join(__dirname, 'app')),
  handler: 'index.handler',
  runtime: lambda.Runtime.NODEJS_22_X,
  // authType はデフォルト値なし (必須)。公開エンドポイントは必ず明示する必要がある
  authType: lambda.WebFunctionAuthType.IAM_AUTH,
});

// 払い出された属性
new cdk.CfnOutput(this, 'Domain', { value: webFn.domainName });
new cdk.CfnOutput(this, 'EndpointArn', { value: webFn.endpointArn });

// IAM 付与 (lambda:InvokeWebFunctionEndpoint を endpointArn に対して付与)
webFn.grants.invoke(myRole);

// ---- パターン 2: 既存の準拠バケットを使う ----
const codeBucket = s3.Bucket.fromBucketName(this, 'CodeBucket', 'my-compliant-bucket');
new lambda.WebFunction(this, 'WebFnFromBucket', {
  code: lambda.WebFunctionCode.fromBucket(codeBucket, 'app.zip'),
  handler: 'index.handler',
  runtime: lambda.Runtime.NODEJS_22_X,
  authType: lambda.WebFunctionAuthType.APPLICATION_MANAGED,
});

// ---- パターン 3: VPC Egress 用 NetworkConnector ----
const vpc = new ec2.Vpc(this, 'Vpc');
const connector = new lambda.NetworkConnector(this, 'Conn', {
  // VPC / サブネット / セキュリティグループを 1 か所で指定
  configuration: lambda.NetworkConnectorConfiguration.vpcEgress({
    vpc,
    vpcSubnets: { subnetType: ec2.SubnetType.PRIVATE_WITH_EGRESS },
    // securityGroups を省略するとデフォルトの SG が作成される
  }),
  // 省略時は operator role (AWSLambdaNetworkConnectorOperatorPolicy) を自動作成
});

new lambda.WebFunction(this, 'WebFnWithVpc', {
  code: lambda.WebFunctionCode.fromAssetToManagedBucket(path.join(__dirname, 'app')),
  handler: 'index.handler',
  runtime: lambda.Runtime.NODEJS_22_X,
  authType: lambda.WebFunctionAuthType.IAM_AUTH,
  // コネクタの latestVersionArn にピン留めされる (同一スタック内のみ指定可能)
  egressNetworkConnector: connector,
});
```

**ポイント:**
- `authType` にはデフォルト値がなく必須です。公開エンドポイントを意図せず作ってしまうことを防ぐ設計になっています。
- `fromAssetToManagedBucket` のステージングには新しい内部カスタムリソースが使われ、`CopyObject` でサーバーサイドコピーを行います。`BucketDeployment` では書き込んだバージョンの ID が取れないため採用されていません。
- `NetworkConnector` は更新のたびに新しい不変バージョンを生み、`WebFunctionProps.egressNetworkConnector` は `latestVersionArn` にピン留めします。この ARN は更新のたびに変わるため、**別スタックのコネクタ参照は synth で拒否されます**。別スタック参照が必要な場合は `NetworkConnector.fromNetworkConnectorVersionArn` で固定バージョンを指定してください。
- 現時点では `WebFunctionTraffic.single()` のみ対応し、加重トラフィックは今後の追加予定です。

### Custom Resource ハンドラーログの機密プロパティ秘匿機能 ([#39541](https://github.com/aws/aws-cdk/pull/39541))

**この機能でできること:**
- CloudFormation は `Ref` / `Fn::GetAtt` をハンドラ呼び出し前に解決して渡すため、`NoEcho` な `CfnParameter` などへの `Ref` を含むプロパティが、カスタムリソースハンドラの CloudWatch ログに平文で出力されてしまう問題を解消する仕組みが導入されました。
- `@aws-cdk/custom-resource-handlers` 内部の `makeHandler` に `redactProperties` オプションが追加され、指定したトップレベルプロパティ名を `ResourceProperties` と `OldResourceProperties` の両方で `*****` に置換してログ出力します。
- 同時に、Provider Framework の `onTimeout` / `safeHandler` などに存在した `ResponseURL` やタイムアウト時 `NoEcho` データの平文出力など、複数の既存のログリークも修正されています。

**ポイント:**
- これは CDK 内部用 (`@aws-cdk/custom-resource-handlers` は非公開パッケージ) の仕組みで、ユーザーが独自に書く Provider framework のカスタムリソースでは `NoEcho` レスポンスのマスクが従来通り有効です。
- `isComplete` が返した `NoEcho` も SUCCESS レスポンスの `NoEcho` 決定に反映されるようになりました。`\"false\"` や `\"0\"` のような文字列の truthy 値でも NoEcho が立つという挙動変更が含まれています (マスクが増える方向のみの変更)。
- ログフォーマットが変わっているため、ログベースのメトリクスフィルタやアラームを使っている場合は注意が必要です。

### core: Validations.acknowledge による文脈スコープの警告抑止 ([#38842](https://github.com/aws/aws-cdk/pull/38842))

**この機能でできること:**
- 1 つの warning `id` が複数の異なる状況で発せられる場合に、ID 単位の `acknowledge` だと静かにさせたくないケースまで一緒に消してしまう問題を解消する仕組みです。警告発生側がコンテキスト (任意のキー / 値マップ) を付与し、抑止側はその一部に対する部分一致で選択的に抑止できます。
- 抑止は `objectLike` の部分一致 (`template.hasResourceProperties` と同じ慣例) で評価されます。指定したキーはすべて一致する必要があり、指定しないキーは制約なしです。

**使用例:**

```typescript
import { Validations } from 'aws-cdk-lib';

// 発生側: 任意のキーで context を付加
Validations.of(scope).addWarning(
  'my-lib:unsupportedActionType',
  'This action type is not supported and will be ignored',
  { context: { service: 'aiops', resource: 'investigation-group' } },
);

// 抑止側: service === 'aiops' に該当するもののみ抑止 (他の service の警告は残る)
Validations.of(scope).acknowledge({
  id: 'my-lib:unsupportedActionType',
  reason: 'aiops actions are attached intentionally',
  where: { service: 'aiops' },
});
```

**ポイント:**
- `reason` が必須なので、選択的に抑止するたびに理由がドキュメント化されます。
- `where` を省略した場合は従来通り該当 ID の全発生を抑止する後方互換動作です。
- コンテキストを持たない警告は非空の `where` では決して捕捉されません。これにより「詳細未付与の警告を誤って静かにさせる」事故が防げます。
- 今回は値の照合は文字列一致のみですが、内部的に value-matcher エンジンを使っているため、将来的に `Match.stringLikeRegexp` 等への拡張が非破壊で可能です。

### CloudWatch: MathExpression / SearchExpression の visible プロパティサポート ([#38774](https://github.com/aws/aws-cdk/pull/38774))

**この機能でできること:**
- `Metric` には従来から存在した `visible` プロパティが、`MathExpression` と `SearchExpression` にも追加されました。ダッシュボードのグラフ上でトップレベルの式を非表示にできるようになります。

**使用例:**

```typescript
import * as cloudwatch from 'aws-cdk-lib/aws-cloudwatch';

const errorRate = new cloudwatch.MathExpression({
  expression: 'errors / invocations * 100',
  usingMetrics: { errors, invocations },
  label: 'Error rate',
  visible: false, // トップレベルの MathExpression をグラフ上で非表示
});

const searchExpr = new cloudwatch.SearchExpression({
  expression: 'SEARCH(\'{AWS/Lambda,FunctionName} MetricName=\"Errors\"\', \'Sum\', 300)',
  label: 'Lambda errors by function',
  visible: false, // SearchExpression も同様
});
```

**ポイント:**
- 未指定時は `undefined` となり、`dropUndefined` で削除されるため既存テンプレートに影響はありません (後方互換)。
- 非表示にした式には自動ラベルが付与されません (既存の `Metric` の挙動と同じ)。
- `AnomalyDetectionMetricOptions` は `MathExpressionOptions` を継承しているため、同じく `visible` が利用可能です。

### Lambda: WebFunction エンドポイントに authType を追加 ([#39620](https://github.com/aws/aws-cdk/pull/39620))

**この機能でできること:**
- `IWebFunctionEndpoint` に必須プロパティ `authType: WebFunctionAuthType` が追加されました。インポートした既存エンドポイントについても `authType` を把握できるようになり、CloudFront Origin 側で `APPLICATION_MANAGED` のエンドポイントを拒否するなどの検証が synth 時に可能になります。
- `WebFunctionEndpointAttributes` にも必須 `authType` が追加され、`fromWebFunctionEndpointAttributes()` では `domainName` / `endpointType` と並んで `authType` を渡す必要があります (ARN からは導出できないため)。

**使用例:**

```typescript
import * as lambda from 'aws-cdk-lib/aws-lambda';

const importedEndpoint = lambda.WebFunctionEndpoint.fromWebFunctionEndpointAttributes(this, 'Imported', {
  endpointArn: 'arn:aws:lambda:...:webfunctionendpoint/...',
  domainName: 'xxx.lambda-web.us-east-1.on.aws',
  endpointType: lambda.WebFunctionEndpointType.URL,
  authType: lambda.WebFunctionAuthType.IAM_AUTH, // 追加必須
});
```

**ポイント:**
- WebFunction L2 (#39210) はまだリリースされていないため、必須プロパティ追加は破壊的変更として扱われずに追加されています。

## 破壊的変更

### L1 CloudFormation リソース定義更新に伴う Id 属性削除 ([#39669](https://github.com/aws/aws-cdk/pull/39669))

L1 リソースは CloudFormation の公開 Resource Schema から自動生成されており、実状を正確に反映するために以下の変更が含まれます。

- **aws-codebuild**: `AWS::CodeBuild::Project` の `Id` 属性が削除されました。
- **aws-dax**: `AWS::DAX::Cluster` の `Id` 属性が削除されました。
- **aws-ec2**: `AWS::EC2::ClientVpnTargetNetworkAssociation` の `Id` 属性が削除されました。

**移行方法:**
- 該当リソースの `attrId` などの参照を使用している場合は、他の属性 (ARN や Ref) に置き換えてください。

### Alpha: redshift-alpha における修飾テーブル名の扱い変更 ([#39304](https://github.com/aws/aws-cdk/pull/39304))

**変更内容:**
- `Table` が `tableName` のドットを、すべてのテーブル操作において `schema.table` または `database.schema.table` として解釈するようになりました。これは grants が従来から行っていた挙動と整合させるためのものです。
- v2.262.0 以降にドット付きの `tableName` で作成されたテーブルは、1 つの識別子 (例: デフォルトスキーマ下の `"analytics.orders"`) として存在していましたが、アップグレード後は `analytics.orders` (スキーマ `analytics` の `orders` テーブル) として扱われます。
- 空のコンポーネントを含む名前は synth 時に失敗するようになります。
- リネームで qualifier (スキーマやデータベース部分) を追加・削除・変更することはできなくなります。

**移行方法:**
- 既存のドット付きテーブル名を持つ `Table` は、意図した `schema.table` / `database.schema.table` の構造になっているか確認してください。
- 1 つの識別子として `"analytics.orders"` のようなテーブルを使い続ける必要がある場合は、Redshift クラスターの `enable_case_sensitive_identifier` の設定とダブルクォートの扱いを含めて PR 本文を参照してください。

## まとめ

Lambda WebFunction の L2 コンストラクト追加が本リリースの目玉で、L1 ではセットアップが煩雑だったコード配布バケット・リビジョン・エンドポイント・VPC Egress コネクタをまとめて扱える構成になりました。あわせてカスタムリソースログの機密値秘匿、警告の文脈スコープ抑止、CloudWatch 表示制御の拡張、EKS 1.37 / Python 3.15 ランタイム対応などが盛り込まれています。L1 の `Id` 属性削除や `redshift-alpha` の修飾名解釈変更など、破壊的変更にも注意してアップグレードしてください。
