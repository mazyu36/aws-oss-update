## 概要

このリリースは、v2.262.0 で `stack.node.addDependency` の速度改善のために導入された変更 (#38314) が、CloudFormation テンプレートの `DependsOn` 句を破壊する不具合を引き起こしていたため、当該機能を revert した緊急パッチリリースです。パフォーマンス最適化に伴うリファクタリングは維持しつつ、機能的な変更のみが元に戻されています。

**リリース:** [v2.262.2](https://github.com/aws/aws-cdk/releases/tag/v2.262.2)

---

## バグ修正

### `core`: `stack.node.addDependency` の高速化変更を revert ([#38417](https://github.com/aws/aws-cdk/pull/38417))

**修正内容:**

- v2.262.0 でマージされた [#38314](https://github.com/aws/aws-cdk/pull/38314) 「`fix(core): stack.node.addDependency gets slower as stacks grow`」の機能変更部分を revert しました。
- 元の PR は、スタック間で `node.addDependency` を利用した際にリソースのカルテシアン積を展開して依存関係を張ることで発生していた超線形 (実測では準指数的) なパフォーマンス劣化を、スタック単位で解決してから同一スタック内でのみ個別リソースまで展開する方式に変更するものでした。
- しかしこの変更は [#38406](https://github.com/aws/aws-cdk/issues/38406) の通り、生成される CloudFormation テンプレートの `DependsOn` 句を破壊する副作用を持っており、依存関係が正しく張られない状況が発生していました。そのため機能的な変更のみが元に戻され、内部 API のリファクタリング (`resource.addResourceDependency` / `stack.addStackDependency` などのリネーム、`dispatchDependencyOperation` を経由するディスパッチフロー) は維持されています。

**影響を受けていた状況:**

- v2.262.0 / v2.262.1 を利用しており、`construct.node.addDependency(otherConstruct)` を用いてスタック間・スタック内で明示的に依存関係を宣言していた CDK アプリケーション。
- 特に、同一スタック内の複数リソース対複数リソースの依存関係を宣言していたケースで、生成される `DependsOn` の欠落・不整合が発生し得ました。

**修正後の状態:**

- v2.262.2 では `node.addDependency` の実装が v2.261.0 相当の挙動に戻り、`DependsOn` 句が期待通りに合成されます。
- v2.262.0 で導入された、大規模なスタック間依存でのパフォーマンス最適化は取り下げられているため、多数のスタックにまたがる `node.addDependency` を利用しているアプリケーションでは、合成時間が v2.261.0 と同等 (最適化前) に戻る点に注意が必要です。

**使用例:**

```typescript
import * as cdk from 'aws-cdk-lib';
import { Construct } from 'constructs';

const app = new cdk.App();

const producer = new cdk.Stack(app, 'Producer');
const consumer = new cdk.Stack(app, 'Consumer');

// スタック間の依存関係 (合成時に反映される Construct レベルの依存)
consumer.node.addDependency(producer);

// スタック内リソース間の依存関係 (`DependsOn` に反映される)
const bucket = new cdk.aws_s3.Bucket(producer, 'Bucket');
const role = new cdk.aws_iam.Role(producer, 'Role', {
  assumedBy: new cdk.aws_iam.ServicePrincipal('lambda.amazonaws.com'),
});
role.node.addDependency(bucket);
// → v2.262.2 では従来通り、Role 側に DependsOn: [Bucket] が確実に生成される
```

**ポイント:**

- v2.262.0 / v2.262.1 を利用中で、`node.addDependency` を活用している場合は、`DependsOn` の生成漏れによるデプロイ順序不整合を避けるため v2.262.2 へのアップグレードを強く推奨します。
- 大規模スタック間の合成速度改善は今回取り下げられているため、パフォーマンス改善は本リリースには含まれません。将来的な再対応を待つ必要があります (関連: [#38406](https://github.com/aws/aws-cdk/issues/38406)) 。
- 内部 API のリファクタリング (`addStackDependency` / `addResourceDependency` へのリネームや `_addStackDependency` / `_addResourceDependency` の内部化) は revert 対象外です。これらの API を直接利用しているケースは稀ですが、シンボル名の変更点は #38314 マージ時点から維持されている点に留意してください。

---

## まとめ

v2.262.0 で導入されたクロススタック依存関係の最適化が `DependsOn` 句の破壊を引き起こしていたため、機能的な変更のみを revert した緊急パッチリリースです。`node.addDependency` を利用しているアプリケーションは v2.262.2 へのアップグレードを推奨します。
