## 概要

AWS CDK v2.265.0 は、Bedrock AgentCore Memory・CloudWatch 複合アラーム・DocumentDB・Kinesis Data Firehose・EC2 の 5 領域にまたがる新機能追加と、`cdk validate` が無限にハングする問題や GovCloud での Secrets Manager ローテーション失敗を含む重要なバグ修正が含まれる、機能追加の多いリリースです。Alpha モジュールでは `glue-alpha` に 2 つの破壊的変更 (Flex ジョブの Glue 5.0 デフォルト化、`Database` の removalPolicy を RETAIN デフォルト化) が含まれるため、該当モジュール利用者はアップグレード時に注意が必要です。

**リリース:** [v2.265.0](https://github.com/aws/aws-cdk/releases/tag/v2.265.0)

## 新機能

### `bedrock-agentcore`: Memory の Kinesis ストリーム配信対応 ([#37527](https://github.com/aws/aws-cdk/pull/37527))

**この機能でできること:**

- `AWS::BedrockAgentCore::Memory` の CloudFormation 新機能 `StreamDeliveryResources` に L2 コンストラクトから対応しました。Memory が保存するイベントを Kinesis Data Streams に自動配信できます。
- `StreamDeliveryContentType` (`MEMORY_RECORDS`) と `StreamDeliveryContentLevel` (`FULL_CONTENT` / `METADATA_ONLY`) の enum が追加され、レコード本文まで配信するかメタデータのみかを型安全に切り替えられます。
- Memory 作成後に `addStreamDeliveryResource()` メソッドでストリーム配信リソースを追加することも可能です。Memory の実行ロールには対象 Kinesis ストリームへの `PutRecord`/`PutRecords`/`ListShards`/`DescribeStream` 権限が自動付与されます。

**使用例:**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as kinesis from 'aws-cdk-lib/aws-kinesis';
import * as agentcore from 'aws-cdk-lib/aws-bedrockagentcore';
import { Construct } from 'constructs';

export class AgentCoreMemoryStack extends cdk.Stack {
  constructor(scope: Construct, id: string, props?: cdk.StackProps) {
    super(scope, id, props);

    // 配信先の Kinesis Data Stream
    const memoryEventStream = new kinesis.Stream(this, 'MemoryEventStream', {
      encryption: kinesis.StreamEncryption.MANAGED,
    });

    // メモリレコードの本文まで含めて配信するパターン
    new agentcore.Memory(this, 'MemoryWithFullStreamDelivery', {
      memoryName: 'memory_with_stream_delivery',
      description: 'Memory that streams full record bodies to Kinesis',
      expirationDuration: cdk.Duration.days(90),
      streamDeliveryResources: [
        agentcore.StreamDeliveryResource.kinesis(memoryEventStream, {
          contentConfigurations: [
            {
              // 現時点で選択可能な type は MEMORY_RECORDS のみ
              type: agentcore.StreamDeliveryContentType.MEMORY_RECORDS,
              // FULL_CONTENT: レコード本文を配信 / METADATA_ONLY: メタデータのみ
              level: agentcore.StreamDeliveryContentLevel.FULL_CONTENT,
            },
          ],
        }),
      ],
    });

    // メタデータのみを別ストリームへ配信するパターン
    const metadataEventStream = new kinesis.Stream(this, 'MetadataEventStream', {
      encryption: kinesis.StreamEncryption.MANAGED,
    });

    const metadataOnlyMemory = new agentcore.Memory(this, 'MemoryWithMetadataOnly', {
      memoryName: 'memory_with_metadata_only_stream_delivery',
      expirationDuration: cdk.Duration.days(90),
    });

    // インスタンス化後にメソッドで追加することも可能
    metadataOnlyMemory.addStreamDeliveryResource(
      agentcore.StreamDeliveryResource.kinesis(metadataEventStream, {
        contentConfigurations: [
          {
            type: agentcore.StreamDeliveryContentType.MEMORY_RECORDS,
            level: agentcore.StreamDeliveryContentLevel.METADATA_ONLY,
          },
        ],
      }),
    );
  }
}
```

**ポイント:**

- `streamDeliveryResources` は CloudFormation の仕様に合わせて配列として定義されていますが、現時点では 1 要素のみ指定可能です (将来の拡張に備えた API 設計)。
- `contentConfigurations` を省略した場合は `MEMORY_RECORDS` + `FULL_CONTENT` のデフォルト構成が自動的に適用されます。
- 対象 Kinesis ストリームへの IAM 権限は Memory の実行ロールに自動付与されるため、ユーザー側で `grantWrite()` を明示的に呼ぶ必要はありません。

### `cloudwatch`: 複合アラームで `AT_LEAST` 式に対応 ([#37693](https://github.com/aws/aws-cdk/pull/37693))

**この機能でできること:**

- 2025 年 11 月に CloudWatch へ追加された「複合アラームでの `AT_LEAST` 関数」を、`AlarmRule` の型付き API で扱えるようになりました。「N 個以上のアラームが特定の状態にある」という条件をコード上で表現できます。
- 新しい `AlarmRule.atLeast()` / `AlarmRule.atLeastNot()` メソッドが追加され、しきい値は `AtLeastThreshold.count(N)` (絶対数) または `AtLeastThreshold.percentage(P)` (割合) で指定します。これまでは `AlarmRule.fromString()` で式文字列を手で組み立てる必要がありましたが、その必要がなくなります。

**使用例:**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as cloudwatch from 'aws-cdk-lib/aws-cloudwatch';
import { Construct } from 'constructs';

export class CompositeAlarmStack extends cdk.Stack {
  constructor(scope: Construct, id: string, props?: cdk.StackProps) {
    super(scope, id, props);

    const metric = new cloudwatch.Metric({ namespace: 'CDK/Test', metricName: 'Metric' });
    const alarm1 = new cloudwatch.Alarm(this, 'Alarm1', { metric, threshold: 100, evaluationPeriods: 3 });
    const alarm2 = new cloudwatch.Alarm(this, 'Alarm2', { metric, threshold: 1000, evaluationPeriods: 3 });
    const alarm3 = new cloudwatch.Alarm(this, 'Alarm3', { metric, threshold: 10000, evaluationPeriods: 3 });

    // 「3 つのアラームのうち 2 つ以上が ALARM 状態」なら発報する
    const twoOrMoreInAlarm = cloudwatch.AlarmRule.atLeast(cloudwatch.AlarmState.ALARM, {
      operands: [alarm1, alarm2, alarm3],
      threshold: cloudwatch.AtLeastThreshold.count(2),
    });

    // 「3 つのアラームのうち 60% 以上が OK 状態でない」なら発報する
    const majorityNotOk = cloudwatch.AlarmRule.atLeastNot(cloudwatch.AlarmState.OK, {
      operands: [alarm1, alarm2, alarm3],
      threshold: cloudwatch.AtLeastThreshold.percentage(60),
    });

    // 既存のルール構築 API と組み合わせて使える
    const rule = cloudwatch.AlarmRule.anyOf(twoOrMoreInAlarm, majorityNotOk);

    new cloudwatch.CompositeAlarm(this, 'CompositeAlarm', { alarmRule: rule });
  }
}
```

**ポイント:**

- `AtLeastThreshold.count(N)` は 1 以上かつ `operands` の要素数以下の整数のみ受け付けます (バリデーション有り)。`AtLeastThreshold.percentage(P)` は 1〜100 の整数のみ受け付けます。
- `atLeast(state, ...)` と `atLeastNot(state, ...)` の 2 メソッド + `AlarmState` enum の組み合わせで表現するため、`ALARM` / `OK` / `INSUFFICIENT_DATA` それぞれの正逆パターンが少ないメソッド数でカバーされます。
- 既存の `AlarmRule.allOf` / `AlarmRule.anyOf` / `AlarmRule.not` / `AlarmRule.fromAlarm` などとネストして組み合わせ可能です。

### `docdb`: マネージドパスワード (Secrets Manager 連携) 対応 ([#35711](https://github.com/aws/aws-cdk/pull/35711))

**この機能でできること:**

- DocumentDB クラスターのマスターユーザーパスワードを、AWS Secrets Manager が自動生成・管理・ローテーションする「マネージドパスワード」機能に対応しました。ユーザーが `masterUser.password` を渡す必要がなくなります。
- 新しく追加されたプロパティは以下の 3 つです。
  - `manageMasterUserPassword: boolean` — Secrets Manager によるパスワード管理を有効化
  - `masterUserSecretKmsKey: kms.IKey` — マネージドシークレットを暗号化する任意の KMS キー (省略時は AWS 管理キー)
  - `rotateMasterUserPassword: boolean` — マネージドシークレットに対して即時ローテーションをトリガー

**使用例:**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as ec2 from 'aws-cdk-lib/aws-ec2';
import * as kms from 'aws-cdk-lib/aws-kms';
import { DatabaseCluster } from 'aws-cdk-lib/aws-docdb';
import { Construct } from 'constructs';

export class DocDbStack extends cdk.Stack {
  constructor(scope: Construct, id: string, props?: cdk.StackProps) {
    super(scope, id, props);

    const vpc = new ec2.Vpc(this, 'Vpc', { maxAzs: 2 });

    // マネージドシークレットの暗号化に使う任意の KMS キー
    const secretKey = new kms.Key(this, 'SecretKey', {
      description: 'KMS key for DocumentDB managed master password',
    });

    new DatabaseCluster(this, 'Cluster', {
      // Secrets Manager にパスワードの生成・管理を任せる (password を指定しない)
      manageMasterUserPassword: true,
      masterUser: {
        username: 'docdbuser',
      },
      // マネージドシークレット暗号化用の KMS キー (省略可)
      masterUserSecretKmsKey: secretKey,
      // 作成直後にローテーションを走らせたいときは true (省略可、デフォルト false)
      // rotateMasterUserPassword: true,
      instanceType: ec2.InstanceType.of(ec2.InstanceClass.R5, ec2.InstanceSize.LARGE),
      vpc,
    });
  }
}
```

**ポイント:**

- `manageMasterUserPassword: true` を指定した場合、`masterUser.password` を同時に指定するとエラーになります。パスワード管理は Secrets Manager 側に完全に委譲する形です。
- 作成されたマネージドシークレットの ARN は、DocumentDB クラスターの `MasterUserSecret` としてクラスター側から参照でき、アプリケーションから Secrets Manager 経由で取得できます。

### `ec2`: Gateway VPC エンドポイントに `ipAddressType` / `dnsRecordIpType` を追加 ([#37900](https://github.com/aws/aws-cdk/pull/37900))

**この機能でできること:**

- `GatewayVpcEndpoint` (S3 / DynamoDB) の L2 コンストラクトに、IPv4 / IPv6 / dualstack を選択するための `ipAddressType` と、DNS レコードの IP タイプを制御する `dnsRecordIpType` が追加されました。
- これまで `InterfaceVpcEndpoint` にのみあった 2 プロパティが Gateway エンドポイントにも揃い、dualstack / IPv6 の Gateway エンドポイントを CDK L2 のまま構築可能になりました (これまでは `CfnVPCEndpoint` へのエスケープが必要でした)。

**使用例:**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as ec2 from 'aws-cdk-lib/aws-ec2';
import { Construct } from 'constructs';

export class VpcEndpointStack extends cdk.Stack {
  constructor(scope: Construct, id: string, props?: cdk.StackProps) {
    super(scope, id, props);

    const vpc = new ec2.Vpc(this, 'Vpc');

    // dualstack で S3 Gateway エンドポイントを作成
    new ec2.GatewayVpcEndpoint(this, 'S3Endpoint', {
      vpc,
      service: ec2.GatewayVpcEndpointAwsService.S3,
      ipAddressType: ec2.VpcEndpointIpAddressType.DUALSTACK,
      // DNS レコードのタイプは省略可 (未指定時はエンドポイントのデフォルト挙動)
      dnsRecordIpType: ec2.VpcEndpointDnsRecordIpType.DUALSTACK,
    });

    // IPv6 のみの DynamoDB Gateway エンドポイント (両プロパティ省略時は従来通り IPv4)
    new ec2.GatewayVpcEndpoint(this, 'DdbEndpoint', {
      vpc,
      service: ec2.GatewayVpcEndpointAwsService.DYNAMODB,
      ipAddressType: ec2.VpcEndpointIpAddressType.IPV6,
      dnsRecordIpType: ec2.VpcEndpointDnsRecordIpType.IPV6,
    });
  }
}
```

**ポイント:**

- 両プロパティは任意で、未指定時は従来通り IPv4 で作成されます (後方互換性あり)。
- 値の enum は既存の `InterfaceVpcEndpoint` と共通のため、既存コードのプロパティを Gateway 側にそのまま流用できます。

### `ec2`: Launch Template の EBS プロパティに `volumeInitializationRate` を追加 ([#36451](https://github.com/aws/aws-cdk/pull/36451))

**この機能でできること:**

- EBS スナップショットからボリュームを復元する際の「ボリューム初期化速度」(volume initialization rate) を、Launch Template のブロックデバイス設定から指定できるようになりました。指定した速度でスナップショットのバックグラウンド初期化が加速され、インスタンス起動直後の I/O パフォーマンス低下を抑えられます。
- `aws-ec2` の `BlockDeviceVolume.ebsFromSnapshot()` および `aws-autoscaling` の対応プロパティに、`volumeInitializationRate: Size` オプションが追加されました。

**使用例:**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as ec2 from 'aws-cdk-lib/aws-ec2';
import { Construct } from 'constructs';

export class LaunchTemplateStack extends cdk.Stack {
  constructor(scope: Construct, id: string, props?: cdk.StackProps) {
    super(scope, id, props);

    declare const snapshotId: string;

    new ec2.LaunchTemplate(this, 'Template', {
      blockDevices: [{
        deviceName: '/dev/xvda',
        volume: ec2.BlockDeviceVolume.ebsFromSnapshot(snapshotId, {
          volumeType: ec2.EbsDeviceVolumeType.GP3,
          // スナップショットの初期化速度 (MiB/s 単位で指定)。値が大きいほど早くフル性能に到達する
          volumeInitializationRate: cdk.Size.mebibytes(300),
        }),
      }],
    });
  }
}
```

**ポイント:**

- `volumeInitializationRate` は EBS スナップショットから復元するボリュームでのみ有効です。空のボリュームには適用されません。
- 値は `cdk.Size` で MiB/s 単位を表現します (例: `Size.mebibytes(300)` → 300 MiB/s)。AWS 側の許容範囲外の値は synth 時のバリデーションで弾かれます。

### `kinesisfirehose`: HTTP エンドポイントおよび Datadog 送信先の追加 ([#33657](https://github.com/aws/aws-cdk/pull/33657))

**この機能でできること:**

- Amazon Data Firehose の配信先として、汎用 `HttpEndpoint` (任意の HTTP 受信先) と、Datadog 専用の `Datadog` L2 コンストラクトが新設されました。これまで CDK では S3・Redshift・OpenSearch などが L2 でサポートされていましたが、HTTP 系はエスケープが必要でした。
- Datadog 送信先は、リージョン別の Logs / Metrics / Configurations エンドポイントを表す `DatadogEndpoint` 静的定数群と、任意 URL を扱う `DatadogEndpoint.of(url)` が用意され、Datadog の正しい intake URL を型付きで指定できます。

**使用例 (HTTP エンドポイント):**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as firehose from 'aws-cdk-lib/aws-kinesisfirehose';
import { Construct } from 'constructs';

export class HttpEndpointStack extends cdk.Stack {
  constructor(scope: Construct, id: string, props?: cdk.StackProps) {
    super(scope, id, props);

    new firehose.DeliveryStream(this, 'HttpDeliveryStream', {
      destination: new firehose.HttpEndpoint({
        endpointConfig: {
          // 受信側の URL (HTTPS が必須)
          url: 'https://example.com/collector',
          // 必要に応じて名前・アクセスキー・共通属性を設定可能
          // name: 'MyHttpEndpoint',
          // accessKey: SecretValue.secretsManager('my-access-key'),
        },
      }),
    });
  }
}
```

**使用例 (Datadog 送信先):**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as firehose from 'aws-cdk-lib/aws-kinesisfirehose';
import { Secret } from 'aws-cdk-lib/aws-secretsmanager';
import { Construct } from 'constructs';

export class DatadogFirehoseStack extends cdk.Stack {
  constructor(scope: Construct, id: string, props?: cdk.StackProps) {
    super(scope, id, props);

    // Datadog の API キーは Secrets Manager から参照
    const apiKey = Secret.fromSecretNameV2(this, 'DatadogApiKey', 'DatadogApiKey');

    new firehose.DeliveryStream(this, 'DatadogDeliveryStream', {
      destination: new firehose.Datadog({
        apiKey,
        // Datadog のリージョン別 intake URL を型付きで指定
        // (Logs / Metrics / Configurations がそれぞれリージョン別に用意されている)
        endpoint: firehose.DatadogEndpoint.LOGS_EU,
        // カスタム URL の場合: firehose.DatadogEndpoint.of('https://.../')
      }),
    });
  }
}
```

**ポイント:**

- `HttpEndpoint` は `bufferingHints` / `retryOptions` / `commonAttributes` / `compression` / `backupMode` / `s3Backup` などの標準的な Firehose 配信オプションに対応しています。
- Datadog 側では US1 / US3 / US5 / AP1 / EU / US Gov などのリージョン別 URL が定数化されており、`LOGS_*` / `METRICS_*` / `CONFIGURATION_*` の 3 系統から選択できます。予期しない URL のタイポを避けられます。

## バグ修正

### `cloudwatch`: コンクリートウィジェットが `IWidget` に代入可能に ([#37695](https://github.com/aws/aws-cdk/pull/37695))

- TypeScript の `exactOptionalPropertyTypes: true` 設定下で、`GraphWidget` などの具体ウィジェットが `IWidget` インターフェースに代入できなかった問題を修正しました。
- 原因は `ConcreteWidget.warnings` / `warningsV2` が「値が `undefined` を取りうる必須プロパティ」として宣言されており、`IWidget` の「オプショナルプロパティ」宣言と型が一致しなかったためです。修正により両者ともオプショナル (`?:`) 宣言に揃えられました。
- ランタイム挙動には変化はなく、コンクリートウィジェット側は引き続き空の警告コレクションを初期値として持ちます。

---

### `core`: `cdk validate` が無限にハングする問題を修正 ([#38510](https://github.com/aws/aws-cdk/pull/38510))

- `cdk validate` コマンドで使われている `cloudformation-validate` のパフォーマンス問題により、状況によっては検証が終わらずコマンドが無限にハングしていました。
- `cloudformation-validate` のバージョンアップにより性能問題が解消され、あわせて診断内容とレイテンシを可視化するメトリクスも追加されました。

---

### `secretsmanager`: GovCloud 向け SAR ローテーションアプリのバージョンを修正 ([#38462](https://github.com/aws/aws-cdk/pull/38462))

- Secrets Manager のシークレットローテーション (`SecretRotation`) が参照する Serverless Application Repository (SAR) のバージョンのうち、`aws-us-gov` パーティション向けの値が GovCloud SAR カタログに実在しないバージョンを指しており、GovCloud での `SecretRotation` を含むスタックが change-set 作成時に必ず失敗していました。
- 対象は MySQL / PostgreSQL / MariaDB / Oracle / SQL Server / Redshift / MongoDB / Db2 の全エンジン、single-user / multi-user 両方式です。修正により、GovCloud SAR カタログに実在する最新バージョンへ差し替えられました。
- `aws` / `aws-cn` の値は変更されていません。GovCloud 環境で `SecretRotation` を利用していたユーザーは、このバージョン以降でようやくデプロイが通るようになります。

---

### `brace-expansion` を 5.0.9 にアップデート (CVE-2026-69152 対応) ([#38520](https://github.com/aws/aws-cdk/pull/38520))

- CDK に同梱される `brace-expansion` 5.0.7 に CVE-2026-69152 (GHSA-rgw5-rvv9-x895) の脆弱性があったため、5.0.9 に更新されました。
- ユーザー側の API 変更はありませんが、脆弱性スキャナで警告が出ていた環境は本バージョンへの更新で解消されます。

## Alpha モジュール

### `glue-alpha`: Flex ジョブの Glue バージョンデフォルトを V5.0 に ([#38543](https://github.com/aws/aws-cdk/pull/38543)) 【破壊的変更】

**この機能でできること:**

- `PySparkFlexEtlJob` と `ScalaSparkFlexEtlJob` のデフォルト Glue バージョンが `GlueVersion.V3_0` (Spark 3.1 / Python 3.7) から `GlueVersion.V5_0` (Spark 3.5 / Python 3.11) に変更されました。V3.0 は既に EOL のためです。
- Python Shell ジョブは変更対象外です (Glue バージョンは pyshell では無視され、Python 3.9 のまま)。

**変更前:**

```typescript
import * as glue from '@aws-cdk/aws-glue-alpha';

// glueVersion 未指定時は暗黙的に V3_0 (EOL) が使われていた
new glue.PySparkFlexEtlJob(this, 'Job', {
  script: glue.Code.fromAsset('path/to/script.py'),
  role,
});
```

**変更後:**

```typescript
import * as glue from '@aws-cdk/aws-glue-alpha';

// glueVersion 未指定時のデフォルトが V5_0 になった
new glue.PySparkFlexEtlJob(this, 'Job', {
  script: glue.Code.fromAsset('path/to/script.py'),
  role,
});

// 従来の V3_0 を維持したい場合は明示指定が必要
new glue.PySparkFlexEtlJob(this, 'LegacyJob', {
  script: glue.Code.fromAsset('path/to/script.py'),
  role,
  glueVersion: glue.GlueVersion.V3_0,
});
```

**移行方法:**

- `V3_0` の挙動 (Spark 3.1 / Python 3.7) に依存しているスクリプトがある場合は、`glueVersion: glue.GlueVersion.V3_0` を明示的に指定してアップデートしてください。
- 特に依存関係が無い場合は、そのままの記述で自動的に V5.0 にアップグレードされます。

### `glue-alpha`: `Database` の removalPolicy デフォルトを `RETAIN` に ([#38535](https://github.com/aws/aws-cdk/pull/38535)) 【破壊的変更】

**この機能でできること:**

- Glue `Database` はテーブルとそのメタデータのコンテナであり、スタックから削除された場合の誤ってデータを失うリスクを避けるため、デフォルトの `removalPolicy` が `RETAIN` に変更されました。
- あわせて `SecurityConfiguration` と `DataQualityRuleset` にも `removalPolicy` プロパティが追加されました (これら 2 つは従来からデフォルトが `RETAIN` のままです)。

**変更前:**

```typescript
import * as glue from '@aws-cdk/aws-glue-alpha';

// Database はデフォルトで DESTROY されていた
new glue.Database(this, 'Database', {
  databaseName: 'my_database',
});
```

**変更後:**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as glue from '@aws-cdk/aws-glue-alpha';

// Database はデフォルトで RETAIN される (スタック削除時にリソースが残る)
new glue.Database(this, 'Database', {
  databaseName: 'my_database',
});

// スタック削除時に一緒に消したい場合は明示的に DESTROY を指定
new glue.Database(this, 'EphemeralDatabase', {
  databaseName: 'my_ephemeral_database',
  removalPolicy: cdk.RemovalPolicy.DESTROY,
});
```

**移行方法:**

- 開発・テスト用スタックなど、スタック削除時に Database も削除したいケースでは、`removalPolicy: cdk.RemovalPolicy.DESTROY` を明示的に指定してください。
- 既存の本番用スタックでは意図せずデータが失われる事故を防ぐ方向の変更のため、多くのユーザーはそのままで問題ありません。

### `glue-alpha`: プレーンテキストの機密情報に警告 ([#38538](https://github.com/aws/aws-cdk/pull/38538))

**この機能でできること:**

- `Connection` や各種 `Job` に渡す任意プロパティ (自由記述の key-value) の中に、パスワード・キー・証明書と思われるキー名 (`password` / `secret` / `token` など) が含まれていた場合、synth 時に警告が表示されるようになりました。
- 該当する値はテンプレートやログにプレーンテキストで残り得るため、警告メッセージ側で「Secrets Manager などの安全な参照方法に置き換える」ことを促す内容が表示されます。あくまで警告であり、ユーザーが正当な非機密値だと判断した場合は無視できます。

**ポイント:**

- 100% 確実に機密かどうかは CDK では判定できないため、パターンマッチベースの警告に留まります。
- 警告に該当する場合は、値そのものではなく `Secret.fromSecretNameV2()` などの参照値を渡す形にリファクタリングすると安全性が高まります。

### `glue-alpha`: `S3Table` の grant が共有バケット全体をカバーする場合に警告 ([#38542](https://github.com/aws/aws-cdk/pull/38542))

**この機能でできること:**

- `S3Table.grantRead()` / `grantWrite()` / `grantReadWrite()` は S3 側の権限を `s3Prefix + '*'` にスコープしていますが、呼び出し側が渡したバケットに対して `s3Prefix` が空だと、そのバケット全体に権限を付与してしまい、他のテーブルが同じバケットを共有しているデータへ意図せずアクセスできてしまうケースがありました。
- 修正後、そのような状況を検知して synth 時に警告を出すようになりました (`Annotations.of` から抑止可能)。バケットを自動生成しているケース (テーブルがバケット全体を所有) は従来通り警告なしです。

**ポイント:**

- 警告が出た場合は、そのテーブル専用のバケットを切り出すか、prefix を指定して権限をスコープするかを検討してください。
- 「意図的にバケット全体への広い権限を付ける」ケースでは、警告を抑止することで従来通り動作します。

- `mediaconnect-alpha` の名前バリデーションが、AWS 側が実際に許可しているアンダースコア (`_`) を弾いていた問題を修正しました。

## まとめ

v2.265.0 は、Bedrock AgentCore Memory の Kinesis 配信・CloudWatch 複合アラームの `AT_LEAST`・DocumentDB のマネージドパスワード・Kinesis Data Firehose の HTTP / Datadog 対応・Gateway VPC エンドポイントの dualstack 対応など、実運用でよく求められる機能が幅広く一度に追加された大型リリースです。GovCloud で機能していなかった Secrets Manager ローテーションや `cdk validate` のハングといった実害の大きい修正も含まれており、GovCloud ユーザーや検証を利用しているユーザーは特に恩恵が大きいでしょう。Alpha モジュール側では `glue-alpha` の Flex ジョブ Glue バージョン変更と `Database` の removalPolicy デフォルト変更という 2 つの破壊的変更が含まれるため、該当モジュール利用者はアップグレード時の挙動差分を必ず確認してください。
