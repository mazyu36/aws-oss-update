## 概要

このリリースでは、AWS Batch 向けの `ConsumableResource` L2 コンストラクトの追加、Bedrock AgentCore Runtime の `platformVersion` サポート、CloudFront Distribution の HTTP → HTTPS リダイレクトをデフォルト化する機能フラグ、OpenSearch の Blue/Green デプロイ関連オプションの追加、CodePipeline L3 コンストラクトの `executionMode` サポートが追加されています。また、CloudFormation の L1 リソース定義の更新に伴う複数の破壊的変更、および Alpha モジュールの Redshift で CloudWatch への監査ログ出力サポートが追加されています。

**リリース:** [v2.273.0](https://github.com/aws/aws-cdk/releases/tag/v2.273.0)

## 新機能

### Batch: ConsumableResource L2 コンストラクトの追加 ([#36971](https://github.com/aws/aws-cdk/pull/36971))

**この機能でできること:**
- AWS Batch の Consumable Resources（ソフトウェアライセンスや API レート制限などの有限リソースをリソースアウェアスケジューリングで管理する機能）を L2 コンストラクトで利用できるようになりました。
- 既存のリソース ARN からのインポートや、権限付与用の `grants` プロパティもサポートされています。

**使用例:**

```typescript
import * as batch from 'aws-cdk-lib/aws-batch';
import * as iam from 'aws-cdk-lib/aws-iam';

// Consumable Resource を作成
const license = new batch.ConsumableResource(this, 'License', {
  consumableResourceName: 'my-software-license',
  totalQuantity: 10,
  // REPLENISHABLE: ジョブ完了後に自動で復元される(デフォルト)
  // NON_REPLENISHABLE: 一度消費すると復元されない
  resourceType: batch.ConsumableResourceType.REPLENISHABLE,
  tags: {
    Team: 'platform',
  },
});

// 権限付与: 読み取り / 更新
const role = new iam.Role(this, 'Role', {
  assumedBy: new iam.ServicePrincipal('batch.amazonaws.com'),
});
license.grants.read(role);    // batch:DescribeConsumableResource, batch:ListJobsByConsumableResource
license.grants.update(role);  // batch:UpdateConsumableResource

// 既存リソースを ARN からインポート
const imported = batch.ConsumableResource.fromConsumableResourceArn(
  this,
  'ImportedLicense',
  'arn:aws:batch:us-east-1:123456789012:consumable-resource/existing-license',
);
```

**ポイント:**
- `totalQuantity` は非負整数（0 も可）である必要があり、小数値は synth 時に拒否されます。
- `consumableResourceName` と `resourceType` を変更するとリソースが置換されます。名前はアカウント / リージョン内で一意である必要があります。
- `batch:ListConsumableResources` はアカウントレベルの API のため、`grants` には含まれていません。

### Bedrock AgentCore: Runtime の platformVersion サポート ([#38924](https://github.com/aws/aws-cdk/pull/38924))

**この機能でできること:**
- `Runtime` L2 コンストラクトに `platformVersion` プロパティが追加され、ランタイムプラットフォーム（`V1` / `V2` など）を選択できるようになりました。
- V2 は新しい AgentCore Runtime で、エラスティックに最適化され、一貫して高速な起動を実現します。

**使用例:**

```typescript
import * as agentcore from 'aws-cdk-lib/aws-bedrockagentcore';
import * as ecr from 'aws-cdk-lib/aws-ecr';

const runtime = new agentcore.Runtime(this, 'Runtime', {
  runtimeName: 'my-agent-runtime',
  agentRuntimeArtifact: agentcore.AgentRuntimeArtifact.fromEcrRepository(
    ecr.Repository.fromRepositoryName(this, 'Repo', 'my-agent'),
    'latest',
  ),
  // V2: 新しいエラスティックな AgentCore Runtime
  // 未指定の場合はサービスデフォルト(現時点では V1)
  platformVersion: 'V2',
});
```

**ポイント:**
- `platformVersion` はオプションで、未指定時には `PlatformVersion` プロパティが emit されません（サービスのデフォルトが適用されます）。
- 既存のスタックに影響を与えない後方互換な変更です。

### CloudFront: Distribution の HTTP → HTTPS リダイレクトをデフォルト化する feature flag の追加 ([#38721](https://github.com/aws/aws-cdk/pull/38721))

**この機能でできること:**
- 新しい feature flag `@aws-cdk/aws-cloudfront:defaultViewerProtocolPolicyRedirectToHttps` を有効化すると、`viewerProtocolPolicy` を明示指定していない動作のデフォルトが `REDIRECT_TO_HTTPS` になります。
- Security Hub の CloudFront.3 コントロールは `allow-all` を使う Distribution を失敗と判定するため、セキュリティ強化に役立ちます。

**使用例:**

```typescript
// cdk.json の context に以下を追加するか、新規プロジェクトでは cdk init 時にデフォルトで有効化される
// "@aws-cdk/aws-cloudfront:defaultViewerProtocolPolicyRedirectToHttps": true

import * as cloudfront from 'aws-cdk-lib/aws-cloudfront';
import * as origins from 'aws-cdk-lib/aws-cloudfront-origins';
import * as s3 from 'aws-cdk-lib/aws-s3';

const bucket = new s3.Bucket(this, 'Bucket');

// feature flag が有効な場合、viewerProtocolPolicy 未指定で REDIRECT_TO_HTTPS が適用される
const distribution = new cloudfront.Distribution(this, 'Dist', {
  defaultBehavior: {
    origin: origins.S3BucketOrigin.withOriginAccessControl(bucket),
    // viewerProtocolPolicy を指定しない: flag ON → REDIRECT_TO_HTTPS, flag OFF → ALLOW_ALL
  },
  additionalBehaviors: {
    '/api/*': {
      origin: origins.S3BucketOrigin.withOriginAccessControl(bucket),
      // 明示指定した場合は flag の有無にかかわらずその値が優先される
      viewerProtocolPolicy: cloudfront.ViewerProtocolPolicy.HTTPS_ONLY,
    },
  },
});
```

**ポイント:**
- feature flag はデフォルトで OFF のため、既存アプリは同一のテンプレートを合成します。
- 明示指定された `viewerProtocolPolicy` の値は flag の設定に関わらず常に優先されます。
- `addBehavior()`、デフォルト動作、`additionalBehaviors` の全てで同じ解決ロジックが適用されます。

### OpenSearch Service: useLatestServiceSoftwareForBlueGreen サポート ([#38499](https://github.com/aws/aws-cdk/pull/38499))

**この機能でできること:**
- `Domain` の `SoftwareUpdateOptions` に `useLatestServiceSoftwareForBlueGreen` プロパティが追加されました。
- Blue/Green デプロイメントがトリガーされたときに、ドメインが自動的に最新のサービスソフトウェアを使用するようにできます。

**使用例:**

```typescript
import * as opensearch from 'aws-cdk-lib/aws-opensearchservice';
import { EngineVersion } from 'aws-cdk-lib/aws-opensearchservice';

new opensearch.Domain(this, 'Domain', {
  version: EngineVersion.OPENSEARCH_2_11,
  // Blue/Green デプロイ時に自動で最新のサービスソフトウェアを使用
  useLatestServiceSoftwareForBlueGreen: true,
  // 従来からある自動ソフトウェア更新との併用も可能
  enableAutoSoftwareUpdate: true,
});
```

**ポイント:**
- `enableAutoSoftwareUpdate` と併用可能で、両方指定した場合も `softwareUpdateOptions` に正しく反映されます。
- どちらも指定しない場合は従来通り `softwareUpdateOptions` は synth されません。

### Pipelines: CodePipeline L3 コンストラクトでの executionMode サポート ([#35022](https://github.com/aws/aws-cdk/pull/35022))

**この機能でできること:**
- `CodePipeline` L3 コンストラクトでも `executionMode` を指定できるようになりました（従来は L2 のみ対応）。
- パイプラインの並列実行モード（`QUEUED` / `PARALLEL` / `SUPERSEDED`）を選択できます。

**使用例:**

```typescript
import * as codepipeline from 'aws-cdk-lib/aws-codepipeline';
import * as pipelines from 'aws-cdk-lib/pipelines';

const pipeline = new pipelines.CodePipeline(this, 'Pipeline', {
  synth: new pipelines.ShellStep('Synth', {
    input: pipelines.CodePipelineSource.gitHub('owner/repo', 'main'),
    commands: ['npm ci', 'npm run build', 'npx cdk synth'],
  }),
  // PARALLEL: 複数実行を並列で走らせる
  // QUEUED: 順番に実行(待機)
  // SUPERSEDED: 新しい実行で古い実行を置き換える(デフォルト)
  executionMode: codepipeline.ExecutionMode.PARALLEL,
});
```

**ポイント:**
- `executionMode` を指定しない場合、CodePipeline のデフォルトである `SUPERSEDED` が適用されます。
- 並列実行モードを利用する場合、パイプライン V2 タイプが必要です。

**この機能でできること:**

- 一部で型互換性のない変更（破壊的変更）が含まれるため、該当サービスを利用している場合は後述の「破壊的変更」セクションを確認してください。

## バグ修正

### Application Auto Scaling: target tracking で custom metric の account / region が黙って無視される問題 ([#36503](https://github.com/aws/aws-cdk/pull/36503))
- 従来、`customMetric` に別アカウント / リージョンの `account` / `region` が設定されていても CloudFormation スキーマが対応していないため黙って無視されていました。
- 修正により、スタックとメトリクスの account/region が明確に異なる場合、synth 時に warning (`@aws-cdk/aws-applicationautoscaling:crossAccountMetricIgnored` / `crossRegionMetricIgnored`) が出力されるようになりました。
- custom metric はスケーリングポリシーと同一アカウント・リージョンのものを使用する必要があります。

### Bedrock AgentCore: Runtime の aws-cn ECR URI の検証 ([#38948](https://github.com/aws/aws-cdk/pull/38948))
- 中国リージョン（aws-cn）の ECR URI は `.amazonaws.com.cn` で終わるため、従来は `InvalidEcrContainerUri` / `InvalidContainerUri` エラーで synth が失敗していました。
- `AgentRuntimeArtifact.fromImageUri()` と `Runtime` の URI 検証を更新し、aws-cn パーティションの ECR URI も受け入れるようになりました。

### CloudFront Origins: Function URL 向け OAC で不足していた権限 ([#35919](https://github.com/aws/aws-cdk/pull/35919))
- Lambda の Dual Auth 要件により、Function URL の呼び出しには `lambda:InvokeFunctionUrl` と `lambda:InvokeFunction`（`invokedViaFunctionUrl: true` 条件付き）の両方が必要になりました。
- `FunctionUrlOrigin.withOriginAccessControl()` でこれまで `lambda:InvokeFunctionUrl` のみを付与していましたが、`lambda:InvokeFunction` も付与するようになり、CloudFront から Function URL への呼び出しが正しく動作するようになりました。
- feature flag なしの即時適用です。

### Core: validation E2001 が有効化されていなかった問題 ([#38920](https://github.com/aws/aws-cdk/pull/38920))
- バリデーションルール E2001 が意図せず無効化されていた問題が修正されました。

### EKS: AccessEntryType.EC2 で access policy の指定が拒否されていた問題 ([#38782](https://github.com/aws/aws-cdk/pull/38782))
- `AccessEntryType.EC2` に `accessPolicies` を指定すると synth 時に拒否されていましたが、実際には EKS API は受け入れます。
- EKS Auto Mode ノードクラスにクラスターアクセスを付与する公式な方法である `AmazonEKSAutoNodePolicy` の付与が、L1 にフォールバックせずに L2 で可能になりました。

```typescript
cluster.grantAccess('nodeAccess', nodeRole.roleArn, [
  eks.AccessPolicy.fromAccessPolicyName('AmazonEKSAutoNodePolicy', {
    accessScopeType: eks.AccessScopeType.CLUSTER,
  }),
], { accessEntryType: eks.AccessEntryType.EC2 });
```

### S3 Deployment: Source.data の objectKey で staging ディレクトリ外に書き込める問題 ([#38921](https://github.com/aws/aws-cdk/pull/38921))
- `Source.data()`（および `Source.jsonData()` / `Source.yamlData()`）に `../config.txt` のような親ディレクトリを含む `objectKey` を渡すと、`cdk synth` / `diff` / `deploy` を実行するマシンの意図しない場所に書き込まれる問題がありました。
- 修正により、`objectKey` が staging ディレクトリ外に解決される場合、`ValidationError` を投げるようになりました。`a/../b.txt` のように解決後にディレクトリ内に戻るキーは引き続き許容されます。

### 依存関係: brace-expansion を 5.0.12 に更新 ([#38929](https://github.com/aws/aws-cdk/pull/38929))
- バンドルされている `brace-expansion` が 5.0.12 にアップデートされました（CVE 対応）。

## Alpha モジュール

### Redshift Alpha: CloudWatch への監査ログ出力サポート ([#36410](https://github.com/aws/aws-cdk/pull/36410))

**この機能でできること:**
- Redshift クラスターの監査ログを S3 だけでなく CloudWatch Logs にも出力できるようになりました。
- 新しい `ClusterLogging` 抽象クラスにより、ログ出力先を型安全に切り替えられます。

**使用例:**

```typescript
import * as redshift from '@aws-cdk/aws-redshift-alpha';
import * as s3 from 'aws-cdk-lib/aws-s3';
import * as ec2 from 'aws-cdk-lib/aws-ec2';

const vpc = new ec2.Vpc(this, 'Vpc');

// CloudWatch Logs に監査ログを出力
new redshift.Cluster(this, 'ClusterWithCloudWatchLogging', {
  masterUser: { masterUsername: 'admin' },
  vpc,
  logging: redshift.ClusterLogging.cloudWatch({
    logExports: [
      redshift.LogExport.CONNECTION_LOG,
      redshift.LogExport.USER_ACTIVITY_LOG,
      redshift.LogExport.USER_LOG,
    ],
  }),
});

// S3 に監査ログを出力(従来相当)
const bucket = new s3.Bucket(this, 'LogBucket');
new redshift.Cluster(this, 'ClusterWithS3Logging', {
  masterUser: { masterUsername: 'admin' },
  vpc,
  logging: redshift.ClusterLogging.s3({
    bucket,
    keyPrefix: 'redshift-audit/',
  }),
});
```

**ポイント:**
- S3 出力時のバケットリソースポリシーは、confused deputy 攻撃を防ぐために `aws:SourceAccount` 条件が自動付与されます。
- 従来の `loggingProperties` プロパティは削除されました（後述の破壊的変更を参照）。

### Redshift Alpha: PUBLIC ユーザー名を拒否 ([#38935](https://github.com/aws/aws-cdk/pull/38935))
- Redshift では `PUBLIC` はグループ名であり、ユーザー名として利用できません。
- `User` コンストラクトおよび Query Provider で `PUBLIC`（大文字小文字を問わず ASCII のみ）がユーザー名として指定された場合、synth 時および Create/Update 実行前に拒否されるようになりました。
- 既存の `PUBLIC` に対する権限付与の削除（Delete）は引き続き可能です。

## 破壊的変更

### L1 CloudFormation リソース定義の更新に伴う破壊的変更 ([#38969](https://github.com/aws/aws-cdk/pull/38969))

L1 リソースは CloudFormation Resource Schema から自動生成されるため、CloudFormation の実態に合わせた互換性のない型変更が含まれます。

主な変更:

- **aws-appstream**: `AWS::AppStream::StackFleetAssociation` の `FleetName` / `StackName` プロパティが immutable に。
- **aws-appsync**: `AWS::AppSync::ApiCache` の `AtRestEncryptionEnabled` / `TransitEncryptionEnabled` が immutable に。
- **aws-bedrockagentcore**: `AWS::BedrockAgentCore::OnlineEvaluationConfig` の `OutputConfig` 属性が削除。
- **aws-cloud9**: `AWS::Cloud9::EnvironmentEC2` の `Id` 属性が削除。
- **aws-config**: `AWS::Config::ConfigurationRecorder` / `AWS::Config::OrganizationConfigRule` の `Id` 属性が削除。
- **aws-datazone**: `AWS::DataZone::PolicyGrant` の `Detail` / `Principal` プロパティが必須に。
- **aws-directoryservice**: `AWS::DirectoryService::MicrosoftAD` の `Id` 属性が削除。
- **aws-lambda**: `AWS::Lambda::NetworkConnector` の `VpcEgressConfiguration.NetworkProtocol` / `SecurityGroupIds` プロパティが必須に。

**移行方法:**
- immutable 化されたプロパティは、変更するとリソースが置換されます。既存リソースへの変更を避けたい場合は値を変更しないでください。
- 必須化されたプロパティ（`DataZone::PolicyGrant` の `Detail`/`Principal`、`Lambda::NetworkConnector` の `NetworkProtocol`/`SecurityGroupIds`）は、未指定だと synth 時にエラーとなります。該当する L1 を直接使っている場合は明示的に値を指定してください。
- 削除された属性（`Id` など）を参照しているコードは、代替の属性に置き換えてください。

### Redshift Alpha: loggingProperties プロパティの削除 ([#36410](https://github.com/aws/aws-cdk/pull/36410))

**変更前:**

```typescript
new redshift.Cluster(this, 'Cluster', {
  masterUser: { masterUsername: 'admin' },
  vpc,
  loggingProperties: {
    loggingBucket: bucket,
    loggingKeyPrefix: 'redshift-audit/',
  },
});
```

**変更後:**

```typescript
new redshift.Cluster(this, 'Cluster', {
  masterUser: { masterUsername: 'admin' },
  vpc,
  logging: redshift.ClusterLogging.s3({
    bucket,
    keyPrefix: 'redshift-audit/',
  }),
});
```

**移行方法:**
- `loggingProperties` の指定を `logging: ClusterLogging.s3({ bucket, keyPrefix })` に書き換えます。
- CloudWatch へ出力したい場合は `ClusterLogging.cloudWatch({ logExports })` を使用します。

### Redshift Alpha: PUBLIC ユーザー名の拒否 ([#38935](https://github.com/aws/aws-cdk/pull/38935))
- `PUBLIC`（ASCII の大文字小文字を問わない）をユーザー名として指定したり、`PUBLIC` ユーザーをインポートしてテーブル権限を付与する操作は拒否されるようになりました。
- 既存の `PUBLIC` 権限の削除（Revoke）は引き続き可能ですが、権限の縮小（narrowing）は拒否されます。
- 通常のユーザー名への移行は引き続き可能です。

## まとめ

本リリースは、AWS Batch の Consumable Resources や Bedrock AgentCore V2 Runtime への対応、CloudFront のセキュアデフォルト化を始めとする複数の L2 機能強化に加えて、重要なセキュリティ修正（S3 Deployment のパストラバーサル、CloudFront OAC の権限不足）と Redshift Alpha の監査ログ CloudWatch 対応を含む内容となっています。L1 の互換性のない変更も含まれるため、該当サービス（AppStream, AppSync, Lambda NetworkConnector, DataZone など）を利用している場合はアップデート時に確認を行ってください。
