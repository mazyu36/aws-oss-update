## 概要

このリリースでは、Bedrock AgentCore `Runtime` L2 に warmup ビルドフック (`buildHooks`) と最小メモリ (`minimumMemory`) が追加され、V2 ランタイムをウォームスタート状態で起動できるようになりました。S3 では `IBucket` からデフォルトのサーバーサイド暗号化モードが参照できるようになり、Lambda には nodejs 26.x ランタイムが追加されています。Docker bundling の `user` 引数エスケープや validation rule ID 内の `::` 衝突などのバグ修正と、L1 自動生成に伴う `aws-lambda` / `aws-paymentcryptography` の破壊的変更も含まれます。

**リリース:** [v2.277.0](https://github.com/aws/aws-cdk/releases/tag/v2.277.0)

## 新機能

### bedrockagentcore: Runtime の build hooks と minimumMemory サポート ([#39695](https://github.com/aws/aws-cdk/pull/39695))

**この機能でできること:**
- AgentCore `Runtime` L2 に、`buildHooks` と `minimumMemory` の 2 つのオプショナルプロパティが追加されました。これらは新しい `CfnRuntime` の `HooksConfiguration` と `ResourceConfigurations` にレンダリングされます。
- `buildHooks` は、サービスがランタイムをビルドする過程でエージェントコンテナに対して呼び出すフックです。現時点では `warmup` フックが `LifecycleHook.httpPost({ path, port? })` で作成可能で、サービスがエージェントをスナップショットする前に走り、全てのセッションがウォーム状態から始まるようにします。
- `minimumMemory` は各ランタイムセッションの最小メモリを `Size` 型で指定し、`MinimumMemoryInMiB` としてレンダリングされます (例: `Size.gibibytes(4)`)。

**使用例:**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as agentcore from 'aws-cdk-lib/aws-bedrockagentcore';

new agentcore.Runtime(this, 'Runtime', {
  runtimeName: 'my_agent',
  agentRuntimeArtifact,
  // V2 プラットフォームでフックと最小メモリが利用可能
  platformVersion: agentcore.PlatformVersion.V2,
  // ビルドフック: 現時点では Build.Warmup のみサポート
  // path: 1-32 文字, "^/[A-Za-z0-9._~/-]*$" にマッチする必要あり
  // port: 8000-12000 の整数 (省略時はサービスがサーバーポートで埋める)
  buildHooks: {
    warmup: agentcore.LifecycleHook.httpPost({ path: '/warmup', port: 8080 }),
  },
  // 最小メモリ: MiB の整数値である必要がある (非整数は synth で失敗)
  minimumMemory: cdk.Size.gibibytes(4),
});
```

**ポイント:**
- `buildHooks` は `{ warmup }` の形で Build フェーズを保持する設計になっており、将来的に他のフェーズのフックが追加されても後方互換を保てる構造です。`lifecycleConfiguration` (セッションタイムアウト) とは別概念の設定です。
- `LifecycleHook` は `PlatformVersion` や `RuntimeAuthorizerConfiguration` と同じく enum-like クラスで、`httpPost()` のような静的ファクトリーで作成します。
- バリデーションはスキーマに沿ってのみ行われ、`path` は 1-32 文字で `^/[A-Za-z0-9._~/-]*$` にマッチすること、`port` は 8000-12000 の整数であることがチェックされます。トークンは検証をスキップされます。
- `minimumMemory` は `SizeRoundingBehavior.FAIL` で変換されるため、MiB の整数でない値は synth 時に失敗します。
- `ResourceConfigurations` は最大 1 要素であるため、`minimumMemory` はリストではなく単一の `Size` を受け取ります。
- `@aws/cloudformation-validate` 1.16.0 のバンドルスキーマが古いため、現時点では `buildHooks` / `minimumMemory` を設定すると synth で `F3002: Additional properties are not allowed` の warning が出ます (エラーではありません)。将来バリデーター側のスキーマが更新されれば解消されます。

### lambda: nodejs 26.x ランタイム追加 ([#39683](https://github.com/aws/aws-cdk/pull/39683))

**この機能でできること:**
- 2026-11 にローンチされる Lambda の Node.js 26 ランタイムに対応し、`lambda.Runtime.NODEJS_26_X` が追加されました。

**使用例:**

```typescript
import * as lambda from 'aws-cdk-lib/aws-lambda';

new lambda.Function(this, 'Fn', {
  runtime: lambda.Runtime.NODEJS_26_X,
  handler: 'index.handler',
  code: lambda.Code.fromAsset('src'),
});
```

### s3: バケットの暗号化モードを IBucket から公開 ([#38312](https://github.com/aws/aws-cdk/pull/38312))

**この機能でできること:**
- `IBucket` にオプショナルな読み取り専用プロパティ `encryption: BucketEncryption` が追加されました。バケットのデフォルトのサーバーサイド暗号化モードをコンシューマ側から確認できるようになり、escape hatch で `CfnBucket` を書き換えた後でも整合的に判定できます。
- `BucketAttributes` にもオプショナルな `encryption` が追加され、`Bucket.fromBucketAttributes` でインポートする際に暗号化モードを宣言できます。

**使用例:**

```typescript
import * as s3 from 'aws-cdk-lib/aws-s3';
import * as kms from 'aws-cdk-lib/aws-kms';

const bucket = new s3.Bucket(this, 'Bucket', {
  encryption: s3.BucketEncryption.KMS,
  encryptionKey: new kms.Key(this, 'Key'),
});

// 作成したバケットの実効的な暗号化モードを参照可能
// 返り値は BucketEncryption | undefined (CDK がモデル化していない / 未解決の場合は undefined)
const mode = bucket.encryption;

// インポートバケットでも encryption を宣言できる
const imported = s3.Bucket.fromBucketAttributes(this, 'Imported', {
  bucketArn: 'arn:aws:s3:::my-bucket',
  // 宣言しない場合は undefined (下流のコンシューマが挙動を切り替えられる)
  encryption: s3.BucketEncryption.S3_MANAGED,
});
```

**ポイント:**
- マッピングは以下の通りです:
  - ルールなし / `SSEAlgorithm` なし / `AES256` → `S3_MANAGED` (S3 は全バケットに SSE-S3 を適用するため、`UNENCRYPTED` は返されません)。
  - `aws:kms` / `aws:kms:dsse` でキー ID なし → `KMS_MANAGED` / `DSSE_MANAGED` (AWS マネージドキー `aws/s3` が使われる)。
  - キー ID (トークン可) あり → `KMS` / `DSSE`。
  - 未解決または CDK がモデル化していない algorithm → `undefined`。
- インポートバケットで `UNENCRYPTED` を宣言した場合は `S3_MANAGED` にマッピングされ、作成バケットとインポートバケットが同じ契約に従います。

## バグ修正

### core: bundling の user 引数が未エスケープ ([#39685](https://github.com/aws/aws-cdk/pull/39685))
- Docker bundling の `user` 引数が適切にエスケープされておらず、不正な形式の値を渡すことで Docker コンテナの内容を操作できてしまう問題を修正しました。

### core: 無効な validation rule ID ([#39684](https://github.com/aws/aws-cdk/pull/39684))
- `SNAPSHOT` ポリシーをサポート外のリソースに設定した際の annotation 警告 ID (例: `@aws-cdk/core:AWS::SQS::QueueSnapshotRemovalPolicyIgnored`) に `::` が含まれ、feature flag `@aws-cdk/core:annotationsInValidationReport` を有効にしていると validation report で `::` が区切り文字として予約されているためエラーになっていた問題を修正しました。annotation の識別子を validation 識別子に変換する際に `::` を `_` にエスケープするようになりました。

## 破壊的変更

### L1 CloudFormation リソース定義更新に伴うプロパティ削除 ([#39701](https://github.com/aws/aws-cdk/pull/39701))

L1 リソースは CloudFormation の公開 Resource Schema から自動生成されており、実状を正確に反映するために以下の変更が含まれます。

- **aws-lambda**: `AWS::Lambda::NetworkConnector` の `VpcEgressConfiguration` 型から `ElasticIpConfiguration` プロパティが削除されました。
- **aws-paymentcryptography**: `AWS::PaymentCryptography::Key` の `ReplicationStatusType` 型から `KmsKeyArn` プロパティが削除されました。
- **aws-paymentcryptography**: `AWS::PaymentCryptography::Key` の `ReplicationStatusType` 型から `KmsKeyId` プロパティが削除されました。

**移行方法:**
- 該当プロパティを使用していた箇所のコードを削除し、CloudFormation の最新スキーマに沿った設定方法に変更してください。

## まとめ

Bedrock AgentCore V2 ランタイムの warmup ビルドフックと最小メモリ設定、S3 デフォルト暗号化モードの `IBucket` 公開、Lambda の nodejs 26.x ランタイム対応が本リリースの主な機能追加です。あわせて Docker bundling の `user` 引数エスケープや validation rule ID のエスケープなど、細かな修正が含まれています。L1 の自動更新に伴う `aws-lambda` / `aws-paymentcryptography` のプロパティ削除が破壊的変更として含まれるため、該当プロパティを利用している場合はアップグレード前にご確認ください。
