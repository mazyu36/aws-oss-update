## 概要

このリリースでは、Bedrock AgentCore の Policy サブモジュールが stable モジュールに昇格し、CloudWatch Logs の `DELIVERY` ログクラスや S3 Deployment のオブジェクトバージョン ID 取得など新機能が複数追加されました。さらに ECS/DynamoDB/core など各方面のバグ修正と、Glue alpha および Route53Resolver alpha における API 再設計と破壊的変更が含まれています。

**リリース:** [v2.269.0](https://github.com/aws/aws-cdk/releases/tag/v2.269.0)

## 新機能

### Bedrock AgentCore の Policy サブモジュールが stable 化 ([#38687](https://github.com/aws/aws-cdk/pull/38687))

**この機能でできること:**
- これまで `@aws-cdk/aws-bedrock-agentcore-alpha` にのみ存在していた `PolicyEngine` / `Policy` / `PolicyStatement` が `aws-cdk-lib/aws-bedrockagentcore` に昇格し、alpha 依存なしで利用できるようになりました。
- Gateway と PolicyEngine を関連付ける `GatewayPolicyEngineConfig` および `PolicyEngineMode` が追加され、Gateway ロールに対して自動的に PolicyEngine の評価権限が付与されます。
- クロスサービス confused deputy 対策として `aws:SourceArn` / `aws:SourceAccount` の条件でサービスプリンシパルをスコープします。

**使用例:**

```typescript
import * as agentcore from 'aws-cdk-lib/aws-bedrockagentcore';

// PolicyEngine を作成
const engine = new agentcore.PolicyEngine(this, 'Engine', {
  mode: agentcore.PolicyEngineMode.ENFORCE, // alpha のデフォルトは LOG_ONLY だったが stable は ENFORCE
});

// PolicyStatement は props オブジェクトベースに変更（fluent builder は廃止）
const statement = new agentcore.PolicyStatement({
  effect: agentcore.PolicyEffect.PERMIT,
  principal: agentcore.PolicyPrincipal.entity('AgentCore::OAuthUser', 'your-client-id'),
  action: agentcore.PolicyAction.one('AgentCore::Action::WeatherTool__get_forecast'),
  resource: agentcore.PolicyResource.instance('AgentCore::Gateway', gateway.gatewayArn),
});

new agentcore.Policy(this, 'Policy', {
  policyEngine: engine,
  statements: [statement],
});

// Gateway と PolicyEngine の関連付け
gateway.policyEngineConfiguration = {
  policyEngine: engine,
};
```

**ポイント:**
- alpha 版からの主な変更点:
  - `PolicyStatement` は fluent builder（`.permit().forPrincipal(...).onAction(...)`）から props オブジェクト形式に変更されました。29 個のチェーンメソッドと `ConditionBuilder` / `ConditionalPolicyStatement` などのクラスは削除されています。
  - Gateway のデフォルト enforcement mode が `LOG_ONLY` から `ENFORCE` に変更されました。従来動作を維持したい場合は明示的に `mode: PolicyEngineMode.LOG_ONLY` を指定してください。
  - `PolicyEngineMode` / `PolicyValidationMode` は public コンストラクタを持たなくなり、static メンバーまたは `of()` メソッドを使う設計に変わりました。
  - policy statement 内の値が検証されるようになったため、alpha で受け入れられていたクォートやバックスラッシュを含む値は synth 時にエラーになります。生の Cedar を扱いたい場合は `definition` または `PolicyStatement.fromCedar()` を使用してください。

### CloudWatch Logs の DELIVERY ログクラス対応 ([#38703](https://github.com/aws/aws-cdk/pull/38703))

**この機能でできること:**
- Lambda vended logs のように S3 や Data Firehose へログを配信する用途向けの `LogGroupClass.DELIVERY` が L2 コンストラクトから選択できるようになりました。
- `DELIVERY` の場合、CDK は既定の 2 年保持を適用せず、CloudWatch Logs がサービス側で管理する保持ポリシーに任せます。

**使用例:**

```typescript
import * as logs from 'aws-cdk-lib/aws-logs';
import * as kms from 'aws-cdk-lib/aws-kms';

// Delivery ログクラスは配信専用（Lambda vended logs などの配信先として使う）
const deliveryLogGroup = new logs.LogGroup(this, 'DeliveryLogGroup', {
  logGroupClass: logs.LogGroupClass.DELIVERY,
  // encryptionKey と deletionProtectionEnabled は DELIVERY でも使用可能
  encryptionKey: new kms.Key(this, 'Key'),
  deletionProtectionEnabled: true,
});
```

**ポイント:**
- CloudWatch Logs が Delivery ログクラスで受け付けない以下のプロパティを同時指定すると synth 時に fail-fast でエラーになります。
  - `retention`（`RetentionDays.INFINITE` を含む。Delivery はユーザーによる保持制御自体が不可）
  - `dataProtectionPolicy`
  - `fieldIndexPolicies`
- 配信先設定（S3 や Firehose）は `AWS::Logs::SubscriptionFilter` を通じて行います。専用の `S3Destination` は後続 PR で提供予定です。
- 既存の `STANDARD` ログクラスは従来通り `TWO_YEARS` の既定保持が適用されます。

### S3 Deployment のオブジェクトバージョン ID 取得 ([#38766](https://github.com/aws/aws-cdk/pull/38766))

**この機能でできること:**
- `BucketDeployment.objectVersionIds` アクセサが追加され、デプロイした各オブジェクトの S3 `VersionId` を `objectKeys` と 1:1 対応するトークン化リストとして取得できます。
- これまで別途 `AwsCustomResource` で `s3:headObject` を呼び出し IAM や依存関係を組み立てていたワークアラウンドが不要になります。

**使用例:**

```typescript
import * as s3 from 'aws-cdk-lib/aws-s3';
import * as s3deploy from 'aws-cdk-lib/aws-s3-deployment';
import * as lambda from 'aws-cdk-lib/aws-lambda';
import * as cdk from 'aws-cdk-lib';

const bucket = new s3.Bucket(this, 'AssetsBucket', {
  versioned: true, // バージョニング必須。未有効の場合、VersionId は空文字列になる
});

const deployment = new s3deploy.BucketDeployment(this, 'DeployAssets', {
  sources: [s3deploy.Source.asset('./lambda-code.zip')],
  destinationBucket: bucket,
  extract: false, // objectVersionIds は extract: false のときのみ利用可能
});

// バージョンピン留めした Lambda コード参照が可能
new lambda.Function(this, 'Fn', {
  runtime: lambda.Runtime.NODEJS_20_X,
  handler: 'index.handler',
  code: lambda.Code.fromBucketV2(
    bucket,
    cdk.Fn.select(0, deployment.objectKeys),
    {
      objectVersion: cdk.Fn.select(0, deployment.objectVersionIds),
    },
  ),
});
```

**ポイント:**
- **オプトイン方式**: `objectVersionIds` を参照した場合のみ、内部の Custom Resource に `OutputObjectVersionIds` プロパティが渡されます。参照しない既存アプリのテンプレート/スナップショットには影響しません。
- **`extract: false` 限定**: `extract: true`（zip 展開）の場合は各ソース zip と宛先オブジェクトが 1:1 対応にならないため、参照すると `ValidationError` が発生します。
- **バケットのバージョニング必須**: バージョニング未有効のバケットでは VersionId が空文字列になります。
- **クロススタック連携**: `objectVersionIds` / `objectKeys` は `Fn::GetAtt` のリストで、スタック間で直接 Output export できないため、`Fn.select(...)` で選択したスカラー値をエクスポートしてください。

## バグ修正

### cdk-nag の警告が抑制できない問題を修正 ([#38787](https://github.com/aws/aws-cdk/pull/38787))
- `Validations.of().acknowledge()` の identifier parser が `::` を単純な namespace セパレータとして扱っていたため、`AwsSolutions::AwsSolutions-IAM4[Policy::arn:AWS::Partition:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole]` のように ARN を含む cdk-nag v3 の識別子が拒否されていました。
- 括弧（`<`, `(`, `[`）で新しいスコープが導入され、スコープ内では `::` を namespace セパレータとして扱わないようパーサを緩和しました。cdk-nag v3 の警告が正しく acknowledge できるようになります。

### マルチ環境アプリで cdk-nag の findings が重複する問題を修正 ([#38707](https://github.com/aws/aws-cdk/pull/38707))
- 複数のスタックや環境を持つアプリで cdk-nag の findings が重複して報告される問題が修正されました。

### tree.json 生成のパフォーマンス改善 ([#38761](https://github.com/aws/aws-cdk/pull/38761))
- tree.json の生成処理がサブツリー数に対して二次的（quadratic）な計算量になっていた問題を修正し、大規模なコンストラクトツリーでの synth 時間を改善しました。

### builtins と AZ に関する不要な警告を抑制 ([#38673](https://github.com/aws/aws-cdk/pull/38673))
- ビルトインリソースおよびアベイラビリティゾーン関連で発生していた不要な警告が抑制されました。

### CloudFormation バリデーションを最新版に更新 ([#38804](https://github.com/aws/aws-cdk/pull/38804))
- 内部で利用している CloudFormation バリデーションのライブラリが最新版に更新されました。

### DynamoDB TableV2 が内部 grants の非推奨警告を出す問題を修正 ([#38806](https://github.com/aws/aws-cdk/pull/38806))
- `TableV2` が公開の `grants` ヘルパーを構築する際に、非推奨となった `TableGrantsProps.encryptedResource` / `policyResource` フィールドを設定していたため、Python 等で `TableV2` を作成するたびに 2 件の非推奨警告が発生していました。
- 内部構築時に非推奨プロパティを指定しないよう修正され、既存の CloudFormation テンプレートや public API には影響しません。

### ECS Windows Fargate の platform version 1.0.0 で ephemeralStorageGiB を許可 ([#37589](https://github.com/aws/aws-cdk/pull/37589))
- Windows タスクは Fargate platform version 1.0.0 から ephemeral storage をサポートしているにもかかわらず、CDK は Linux と同じく 1.4.0 未満で `EphemeralStorageGibFeatureRequires` を throw していました。
- OS ファミリを判別し、Windows タスクでは platform version 1.0.0 でも `ephemeralStorageGiB` を許容するよう修正されました。
- 併せて `TaskDefinition.runtimePlatform` の public getter が追加されています。

**修正後の使用例:**

```typescript
import * as ecs from 'aws-cdk-lib/aws-ecs';

const taskDef = new ecs.FargateTaskDefinition(this, 'WinTask', {
  runtimePlatform: {
    operatingSystemFamily: ecs.OperatingSystemFamily.WINDOWS_SERVER_2019_CORE,
    cpuArchitecture: ecs.CpuArchitecture.X86_64,
  },
  cpu: 1024,
  memoryLimitMiB: 2048,
  ephemeralStorageGiB: 40, // Windows Fargate では platform version 1.0.0 でも指定可能
});

new ecs.FargateService(this, 'WinService', {
  cluster,
  taskDefinition: taskDef,
  platformVersion: ecs.FargatePlatformVersion.VERSION1_0,
});
```

### ECS サービスから最後のターゲットグループを削除しても反映されない問題を修正 ([#38776](https://github.com/aws/aws-cdk/pull/38776))
- CDK は `AWS::ECS::Service` の `LoadBalancers` プロパティを、ターゲットグループが無い場合に一律省略していました。CloudFormation は「プロパティ省略」を「現状維持」、「空配列」を「登録解除」として扱うため、最後のターゲットグループを削除する変更がデプロイに反映されないバグがありました。
- フィーチャーフラグ `@aws-cdk/aws-ecs:removeEmptyLoadBalancers` を導入し、ターゲットグループが無い場合に `LoadBalancers: []` を出力するよう変更しました。フラグは `FlagType.BugFix` / `recommendedValue: true` のため、新規アプリでは自動的に有効、既存アプリではオプトインです。

**cdk.json 例:**

```json
{
  "context": {
    "@aws-cdk/aws-ecs:removeEmptyLoadBalancers": true
  }
}
```

### lambda-go の go build パス引数のエスケープ ([#38785](https://github.com/aws/aws-cdk/pull/38785))
- `lambda-go` バンドラーが生成する `go build` のパス引数のエスケープ処理が改善されました。

### s3-deployment のログ出力サニタイズ（CWE-117/93 対策） ([#37670](https://github.com/aws/aws-cdk/pull/37670))
- BucketDeployment のカスタムリソースハンドラーで、ログ出力に含まれる制御文字や改行を全てサニタイズするよう修正されました。CWE-117（ログインジェクション）および CWE-93（CRLF インジェクション）対策です。

## Alpha モジュール

### glue-alpha: Job パラメータの整合性を保証 ([#38480](https://github.com/aws/aws-cdk/pull/38480))

**変更内容:**
- Glue ジョブコンストラクトは、コンストラクトが管理する引数および Glue の予約引数を `defaultArguments` から渡すことを拒否するようになりました。これにより、各引数の設定経路は「専用 props」または「`defaultArguments` によるエスケープハッチ」のいずれか一方に統一され、二重定義による設定の食い違いや、`defaultArguments` によるセキュアデフォルトの上書きが不可能になります。
- 以下の引数を `defaultArguments` で渡すと synth 時に `ValidationError` が発生します。
  - **コンストラクト管理**: `--enable-continuous-cloudwatch-log`, `--continuous-log-logGroup`, `--continuous-log-logStreamPrefix`, `--continuous-log-conversionPattern`, `--enable-continuous-log-filter`, `--enable-metrics`, `--enable-observability-metrics`, `--enable-spark-ui`, `--spark-event-logs-path`, `--job-language`, `--class`, `--extra-jars`, `--user-jars-first`, `--extra-py-files`, `--extra-files`, `library-set`
  - **Glue 予約**: `--debug`, `--mode`, `--JOB_NAME`, `--endpoint`
- 該当機能を無効化していても（例: `enableMetrics: false`）、対応する引数は予約されたままになり `defaultArguments` から再有効化することはできません。
- 継続 CloudWatch ロギングが有効かつ `SecurityConfiguration.cloudWatchEncryption` が未設定の場合、プレーンテキストで機微情報がログに残るリスクを警告するようになりました。

**変更前:**

```typescript
new glue.SparkJob(this, 'Job', {
  // ...
  defaultArguments: {
    '--enable-continuous-cloudwatch-log': 'false', // 従来は暗黙に上書きされる
  },
});
```

**変更後:**

```typescript
new glue.SparkJob(this, 'Job', {
  // ...
  continuousLogging: { enabled: false }, // 専用 prop 経由で設定
});
```

### glue-alpha: Workflow Trigger API の全面的な再設計 ([#38579](https://github.com/aws/aws-cdk/pull/38579))

**変更内容:**
- `Action` および `Condition` はプレーンなオブジェクトから抽象クラス + factory メソッドに変更され、job / crawler の選択がコンパイル時に強制されます。実行時の XOR チェックは削除されました。
- `IWorkflow` に全ての trigger メソッドが定義され、imported workflow でも event trigger や conditional trigger を追加できるようになりました。
- スケジュール系メソッドが統一され、`addScheduledTrigger` + `TriggerSchedule.daily()` / `weekly()` / `cron()` / `expression()` の組み合わせに変更されました。
- 全ての `addXxxTrigger` メソッドは `CfnTrigger`（L1 型）ではなく `ITriggerRef` を返します。

**変更前:**

```typescript
workflow.addDailyScheduledTrigger('DailyTrigger', {
  actions: [{ job: myJob }],
});

workflow.addConditionalTrigger('ConditionalTrigger', {
  actions: [{ job: nextJob }],
  conditions: [{ job: myJob, state: glue.JobState.SUCCEEDED }],
});

workflow.addNotifyEventTrigger('EventTrigger', {
  actions: [{ job: myJob }],
});
```

**変更後:**

```typescript
workflow.addScheduledTrigger('DailyTrigger', {
  schedule: glue.TriggerSchedule.daily(),
  actions: [glue.Action.job(myJob)],
});

workflow.addConditionalTrigger('ConditionalTrigger', {
  actions: [glue.Action.job(nextJob)],
  conditions: [glue.Condition.job(myJob, glue.JobState.SUCCEEDED)],
});

// addNotifyEventTrigger は addEventTrigger にリネーム
workflow.addEventTrigger('EventTrigger', {
  actions: [glue.Action.job(myJob)],
});
```

**移行方法:**
- `Action.job(job)` / `Action.crawler(crawler)` を使用してください。crawler は `ICrawlerRef`（`CfnCrawler` または `CfnCrawler.fromCrawlerName(...)`）で参照します。
- `Condition.job(job, state)` / `Condition.crawler(crawler, crawlState)` を使用してください。`state` / `crawlState` は必須引数です。
- `addDailyScheduledTrigger` / `addWeeklyScheduledTrigger` / `addCustomScheduledTrigger` は全て `addScheduledTrigger` に統合されました。`schedule` プロパティで `TriggerSchedule.daily()` / `weekly()` / `cron(...)` を指定します。
- `addNotifyEventTrigger` は `addEventTrigger` に、`NotifyEventTriggerOptions` は `EventTriggerOptions` にリネームされています。

### glue-alpha: Partition Projection のバリアントを内部状態化 ([#38726](https://github.com/aws/aws-cdk/pull/38726))

**変更内容:**
- `PartitionProjectionConfiguration` のバリアント別フィールド（`integerRange`, `dateRange`, `interval`, `digits`, `format`, `intervalUnit`, `values`）が public から外され、`type` のみ public になりました。
- DATE 型の projection では `interval` / `intervalUnit` が `step: DateProjectionStep` に統合され、両方セットが必須になりました。

**変更前:**

```typescript
{
  type: glue.PartitionProjectionType.DATE,
  interval: 1,
  intervalUnit: glue.DateIntervalUnit.DAYS,
}
```

**変更後:**

```typescript
{
  type: glue.PartitionProjectionType.DATE,
  step: { interval: 1, intervalUnit: glue.DateIntervalUnit.DAYS },
}
```

### glue-alpha: Connection の VPC 配置を値オブジェクトでモデル化 ([#38729](https://github.com/aws/aws-cdk/pull/38729))

**変更内容:**
- `ConnectionOptions` の `subnet` / `vpc` / `vpcSubnets` プロパティが削除され、単一の `network` プロパティに置き換えられました。ランタイム throw で co-optional をチェックしていたコードが不要になり、無効な組み合わせがコンパイル時に排除されます。

**変更前:**

```typescript
new glue.Connection(this, 'Conn', {
  type: glue.ConnectionType.JDBC,
  properties: { /* ... */ },
  vpc,
  vpcSubnets: { subnetType: ec2.SubnetType.PRIVATE_WITH_EGRESS },
});
```

**変更後:**

```typescript
new glue.Connection(this, 'Conn', {
  type: glue.ConnectionType.JDBC,
  properties: { /* ... */ },
  network: glue.ConnectionNetwork.vpc(vpc, {
    subnetType: ec2.SubnetType.PRIVATE_WITH_EGRESS,
  }),
  // または: network: glue.ConnectionNetwork.subnet(mySubnet)
});
```

### route53resolver-alpha: FirewallRuleGroupAssociation が mutationProtection / name を無視していた問題を修正 ([#38795](https://github.com/aws/aws-cdk/pull/38795))

**変更内容:**
- `FirewallRuleGroupAssociation` は `mutationProtection` / `name` プロパティを宣言していたにもかかわらず、L1 の `CfnFirewallRuleGroupAssociation` に渡していなかったため、両プロパティは silently に無視されていました。
- 両プロパティを L1 に正しく渡すよう修正しました。`mutationProtection` は `ENABLED` / `DISABLED` にマッピングされ、未設定時は Route 53 のサービスデフォルト（`DISABLED`）になります（以前ドキュメントされていた `true` からデフォルト値が変更されています）。

**破壊的変更の影響:**
- `mutationProtection: true` を設定していた stack では、再デプロイ時にミューテーション保護が有効になり、以降は CloudFormation の update / delete がブロックされます。解除するには `false` に戻す必要があります。
- `name` を設定していた stack では、その値がテンプレートに書き込まれ、Association が置換される可能性があります。

```typescript
new route53resolver.FirewallRuleGroupAssociation(this, 'Assoc', {
  firewallRuleGroup,
  vpc,
  priority: 101,
  mutationProtection: true, // ← 従来無視されていたが今後は正しく反映される
  name: 'my-association',   // ← 同上
});
```

## まとめ

AWS CDK v2.269.0 は、Bedrock AgentCore Policy の GA 昇格と CloudWatch Logs / S3 Deployment / ECS 周りのユーザーインパクトの大きい機能追加・バグ修正を含むリリースです。stable 側での破壊的変更はありませんが、alpha 側の Glue および Route53Resolver では GA 前の API 見直しに伴う複数の破壊的変更があるため、該当モジュールを利用している場合は上記の移行方法を参考にコードを更新してください。
