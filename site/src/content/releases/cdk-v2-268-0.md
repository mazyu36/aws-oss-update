## 概要

AWS CDK v2.268.0 は、AWS Elemental MediaLive の新 L2 コンストラクト (alpha) 追加、EC2 `LaunchTemplate` の `CpuOptions` 対応、CodeBuild Lambda ビルドイメージへの Node.js 24 追加、`BucketDeployment` ハンドラの ARM64 (Graviton) 化といった機能追加に加え、外部シンボリックリンクを含むアセットのバリデーション、CloudFormation 合成時の循環依存チェックの復活、`aws-eks-v2` からの L1 コンストラクトエクスポートなど、実運用に効く修正が入ったリリースです。破壊的変更として、L1 CloudFormation リソース定義の大規模更新に伴い多数のリソースが削除・属性変更されています。Alpha モジュールでは `glue-alpha` の `DataQualityRuleset` API を GA 前にリファレンス型ベースへ整理した破壊的変更が含まれます。

**リリース:** [v2.268.0](https://github.com/aws/aws-cdk/releases/tag/v2.268.0)

## 新機能

### `medialive`: AWS Elemental MediaLive の新 L2 コンストラクト (alpha) ([#38563](https://github.com/aws/aws-cdk/pull/38563))

**この機能でできること:**

- AWS Elemental MediaLive を CDK から宣言的に扱える新しい alpha モジュール `@aws-cdk/aws-medialive-alpha` が追加されました。従来は L1 (`CfnChannel`) で複雑な JSON エンコード設定を書き下すしかありませんでした。
- 入力 (`Input`) / 入力セキュリティグループ (`InputSecurityGroup`) / チャンネル (`Channel`) に加え、MediaLive Anywhere 系リソース (`Network` / `Cluster` / `ChannelPlacementGroup` / `SdiSource`) をカバーします。
- `InputConfiguration.srtCaller()` / `srtListener()` / `mp4File()` / `mediaConnectRouter()` のように、入力タイプごとにファクトリメソッドが分かれており、SRT の暗号化パスフレーズを Secrets Manager から参照渡し (`ISecret`) で持たせるなど、L2 らしいエスケープを回避した書き方ができます。
- Encode は `EncodeConfiguration.video()` / `.audio()`、コーデックは `VideoCodecSettings.h264(...)` / `AudioCodecSettings.aac(...)` などのファクトリで型付きに指定します。ビットレート/フレームレートも `Bitrate.mbps()` / `Framerate.FPS_30` のように単位付き value object です。
- 出力先は `OutputGroupConfiguration.hls(...)` などのファクトリと、`OutputDestination.toBucket(bucket, prefix)` のような destination helper で組み合わせます。S3 バケットの権限付与など、CDK 側で必要なグラントも自動で処理されます。
- `Channel` は `role` を省略すると `medialive.amazonaws.com` を principal とする IAM ロールを自動生成します。
- `@aws-cdk/aws-mediaconnect-alpha` との統合として `RouterOutputConfiguration.mediaLiveInput()` が追加されており、`InputConfiguration.mediaConnectRouter()` で作った入力に配信できます。それ以外の入力タイプに向けると synth は通りますが deploy で失敗する仕様です。

**使用例:**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as s3 from 'aws-cdk-lib/aws-s3';
import * as medialive from '@aws-cdk/aws-medialive-alpha';
import { Bitrate } from '@aws-cdk/aws-medialive-alpha';
import { Construct } from 'constructs';

export class MediaLiveStack extends cdk.Stack {
  constructor(scope: Construct, id: string, props?: cdk.StackProps) {
    super(scope, id, props);

    const bucket = new s3.Bucket(this, 'HlsBucket');

    // SRT Caller 入力: MediaLive 側から SRT リスナーへ接続する
    const input = new medialive.Input(this, 'SrtInput', {
      inputName: 'my-srt-input',
      input: medialive.InputConfiguration.srtCaller([
        {
          srtListenerAddress: '203.0.113.10',
          srtListenerPort: 5000,
        },
      ]),
    });

    // 映像エンコード設定 (H.264 720p CBR 3Mbps @ 30fps)
    const video = medialive.EncodeConfiguration.video({
      name: 'video_720p',
      codec: medialive.VideoCodecSettings.h264({
        rateControl: medialive.H264RateControl.cbr({ bitrate: Bitrate.mbps(3) }),
        framerate: medialive.Framerate.FPS_30,
      }),
      width: 1280,
      height: 720,
    });

    // 音声エンコード設定 (AAC 192kbps)
    const audio = medialive.EncodeConfiguration.audio({
      name: 'audio_aac',
      codec: medialive.AudioCodecSettings.aac({ bitrate: Bitrate.kbps(192) }),
    });

    // チャンネル: 入力 → エンコード → HLS 出力を S3 バケットへ
    new medialive.Channel(this, 'Channel', {
      inputs: [{ input }],
      outputGroups: [
        medialive.OutputGroupConfiguration.hls({
          name: 'hls',
          destinations: [medialive.OutputDestination.toBucket(bucket, 'live/stream')],
          outputs: [{ encodes: [video, audio], outputName: 'hls_out' }],
        }),
      ],
      // role を省略した場合は medialive.amazonaws.com の service principal で自動生成される
    });
  }
}
```

**ポイント:**

- Alpha モジュールなので API は非互換変更を含み得ます。本番投入前に README の「stability banner」を必ず確認してください。
- SRT Listener 入力は `InputSecurityGroup` (許可 CIDR リスト) が必須です。暗号化を有効化する場合は `passphraseSecret: ISecret` を渡すと ARN 参照で解決され、テンプレートには平文が出ません。
- 既存の Input を取り込みたい場合は `medialive.Input.fromInputArn(scope, id, arn)`、既存の InputSecurityGroup は `medialive.InputSecurityGroup.fromInputSecurityGroupArn(scope, id, arn)` で import できます。
- MediaLive のスケジュール / チャンネル起動制御まではまだカバーされていません (アルファ初版のスコープ外)。

### `ec2`: `LaunchTemplate` で `CpuOptions` をサポート ([#38193](https://github.com/aws/aws-cdk/pull/38193))

**この機能でできること:**

- `CfnLaunchTemplate` (L1) には従来から `CpuOptions` プロパティがありましたが、L2 の `LaunchTemplate` からは指定できず、L1 エスケープハッチに落ちる必要がありました。
- `LaunchTemplateProps.cpuOptions` に `LaunchTemplateCpuOptions` を渡せるようになりました。フィールドは以下の 4 つで、明示指定したものだけが L1 に出力されます (デフォルト挙動は変わらないので後方互換)。
  - `coreCount` (`number`): インスタンスの CPU コア数
  - `threadsPerCore` (`number`): コアあたりのスレッド数。マルチスレッド無効化には `1` を指定
  - `nestedVirtualization` (`boolean`): ネスト仮想化を有効化 (対応インスタンスタイプで利用可能)
  - `amdSevSnp` (`boolean`): AMD SEV-SNP を有効化 (M6a / R6a / C6a のみ対応)
- `nestedVirtualization` / `amdSevSnp` は `boolean` で受け取り、内部で CloudFormation 側の `'enabled'` / `'disabled'` 文字列にマップされます (既存の `nitroEnclaveEnabled` と同じ設計方針)。

**使用例:**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as ec2 from 'aws-cdk-lib/aws-ec2';
import { Construct } from 'constructs';

export class LaunchTemplateStack extends cdk.Stack {
  constructor(scope: Construct, id: string, props?: cdk.StackProps) {
    super(scope, id, props);

    new ec2.LaunchTemplate(this, 'Lt', {
      instanceType: ec2.InstanceType.of(ec2.InstanceClass.M6A, ec2.InstanceSize.LARGE),
      machineImage: ec2.MachineImage.latestAmazonLinux2023(),

      // ★ 新規追加: CPU オプション
      cpuOptions: {
        // CPU コア数 (デフォルトはインスタンスタイプに依存)
        coreCount: 2,

        // コアあたりのスレッド数。1 を指定するとマルチスレッド無効
        threadsPerCore: 1,

        // ネスト仮想化を有効化 (対応インスタンスタイプのみ)
        nestedVirtualization: true,

        // AMD SEV-SNP を有効化 (M6a / R6a / C6a のみ)
        amdSevSnp: true,
      },
    });
  }
}
```

**ポイント:**

- 4 フィールドはすべて optional で、指定しなかったフィールドは L1 テンプレートにも出力されません。既存のテンプレートに `cpuOptions` を追加してもデフォルト挙動が消える心配はありません。
- `amdSevSnp` / `nestedVirtualization` はインスタンスタイプ側で対応している必要があります。非対応インスタンスタイプに指定した場合は EC2 側のデプロイ時エラーで弾かれます。

### `codebuild`: Lambda ビルドイメージに Node.js 24 定数を追加 ([#38471](https://github.com/aws/aws-cdk/pull/38471))

**この機能でできること:**

- CodeBuild の Lambda ビルドイメージ (Amazon Linux 2023 ベース) で Node.js 24 系イメージが利用可能になったため、CDK 側にも定数が追加されました。
- x86-64 は `LinuxLambdaBuildImage.AMAZON_LINUX_2023_NODE_24`、aarch64 (Graviton) は `LinuxArmLambdaBuildImage.AMAZON_LINUX_2023_NODE_24` として利用可能です。既存の Node.js 22 定数と同じパターン (#34197 と同型) です。

**使用例:**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as codebuild from 'aws-cdk-lib/aws-codebuild';
import { Construct } from 'constructs';

export class CodeBuildLambdaStack extends cdk.Stack {
  constructor(scope: Construct, id: string, props?: cdk.StackProps) {
    super(scope, id, props);

    // x86-64 Lambda ビルドイメージ (Node.js 24)
    new codebuild.Project(this, 'ProjectX86', {
      environment: {
        buildImage: codebuild.LinuxLambdaBuildImage.AMAZON_LINUX_2023_NODE_24,
      },
      buildSpec: codebuild.BuildSpec.fromObject({
        version: '0.2',
        phases: { build: { commands: ['node --version', 'npm ci', 'npm run build'] } },
      }),
    });

    // aarch64 (Graviton) Lambda ビルドイメージ (Node.js 24)
    new codebuild.Project(this, 'ProjectArm', {
      environment: {
        buildImage: codebuild.LinuxArmLambdaBuildImage.AMAZON_LINUX_2023_NODE_24,
      },
      buildSpec: codebuild.BuildSpec.fromObject({
        version: '0.2',
        phases: { build: { commands: ['node --version', 'npm ci', 'npm run build'] } },
      }),
    });
  }
}
```

**ポイント:**

- Lambda ベースの CodeBuild は VPC / Docker / ローカルキャッシュ非対応など制約があるため、通常の CodeBuild と混在させる場合は用途に応じて選び分けてください。

### `s3-deployment`: `BucketDeployment` ハンドラを ARM64 (Graviton) で実行 ([#37174](https://github.com/aws/aws-cdk/pull/37174))

**この機能でできること:**

- `BucketDeployment` の裏で動く Custom Resource Lambda ハンドラを、常に ARM64 (Graviton) アーキテクチャで実行するようになりました。実行時間あたり単価が x86_64 より安いため、同じ仕事量でトータルコストが下がります。
- ハンドラは CDK 内部で管理する固定コードで、ユーザーが差し替える対象ではないため、`architecture` プロパティとしては表に出さず内部でピン留めする設計を採っています。
- 同梱の AWS CLI v1 レイヤーも純 Python + 実行時にネイティブ拡張は使わない (PyYAML の C 拡張は Python 3.13 ABI 不一致で無視されピュア Python にフォールバック) ため、アーキ移行での挙動差はありません。
- シングルトンハンドラの UUID は変わらないので、既存スタックでは Lambda 関数の in-place 更新 (`Architectures` プロパティのみ変更) となり、リソース置換は発生しません。

**使用例:**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as s3 from 'aws-cdk-lib/aws-s3';
import * as s3deploy from 'aws-cdk-lib/aws-s3-deployment';
import { Construct } from 'constructs';

export class BucketDeployStack extends cdk.Stack {
  constructor(scope: Construct, id: string, props?: cdk.StackProps) {
    super(scope, id, props);

    const bucket = new s3.Bucket(this, 'Site');

    // 使い方は従来通り。ハンドラは自動的に ARM64 で実行される
    new s3deploy.BucketDeployment(this, 'Deploy', {
      sources: [s3deploy.Source.asset('./website')],
      destinationBucket: bucket,
    });
  }
}
```

**ポイント:**

- ユーザーコード側でハンドラのアーキ切り替えはできません。もし何か理由で x86_64 が必要になった場合は自前のカスタムリソースに置き換える必要があります (通常のユースケースでは不要)。
- 前バージョン (v2.267.0) の 128MB → 1024MB のメモリ引き上げと組み合わさり、`BucketDeployment` の速度・コストは大幅に改善されています。

### `l1`: L1 CloudFormation リソース定義の更新 ([#38732](https://github.com/aws/aws-cdk/pull/38732), [#38645](https://github.com/aws/aws-cdk/pull/38645), [#38693](https://github.com/aws/aws-cdk/pull/38693)) 【破壊的変更】

- L1 リソースは AWS CloudFormation の Public Resource Schemas から自動生成されます。今回の更新ではスキーマ側の変更に追従して、多数のリソース・プロパティ・属性が変更・削除されています。
- 主要な変更 (詳細はリリースノート参照):
  - **リソース削除**: `AWS::Athena::Session`, `AWS::BCMDataExports::Table`, `AWS::Bedrock::DefaultPromptRouter`, `AWS::Bedrock::ModelInvocationJob`, `AWS::BedrockAgentCore::Browser`, `AWS::BedrockAgentCore::CodeInterpreter`, `AWS::BedrockAgentCore::TokenVault`, `AWS::CloudFormation::ResourceScan`, `AWS::CodeArtifact::Package`, `AWS::CodeBuild::Sandbox`, `AWS::DynamoDB::Export`, `AWS::ElastiCache::ReservedCacheNode`, `AWS::EMR::NotebookExecution`, `AWS::Events::Replay`, `AWS::FIS::SafetyLever`, `AWS::GreengrassV2::Component`, `AWS::GreengrassV2::CoreDevice`, `AWS::IdentityStore::AllGroupMemberships`, `AWS::ImageBuilder::AllImageBuildVersions` ほか多数、`AWS::MediaLive::Offering`, `AWS::MediaPackage::HarvestJob`, `AWS::MemoryDB::MultiRegionParameterGroup`, `AWS::MemoryDB::ReservedNode`, `AWS::Omics::Reference`, `AWS::OSIS::PipelineBlueprint`, `AWS::Personalize::DataDeletionJob`, `AWS::Personalize::Recipe`, `AWS::RedshiftServerless::RecoveryPoint`, `AWS::SageMaker::ModelCardExportJob`, `AWS::SageMaker::MonitoringScheduleAlert`, `AWS::SageMaker::TransformJob`, `AWS::Signer::SigningJob`, `AWS::SSM::Session`, `AWS::SSO::ApplicationProvider`, `AWS::StepFunctions::MapRun`, `AWS::Transcribe::MedicalTranscriptionJob`。
  - **`Id` 属性の削除**: `AWS::CertificateManager::Certificate`, `AWS::CodeBuild::SourceCredential`, `AWS::DAX::ParameterGroup`, `AWS::DMS::Endpoint` / `EventSubscription` / `ReplicationSubnetGroup`, `AWS::DocDB::DBClusterParameterGroup` / `DBSubnetGroup`, `AWS::Glue::Classifier` / `Connection` / `CustomEntityType` / `DataQualityRuleset` / `MLTransform` / `SecurityConfiguration` / `TableOptimizer` / `Workflow`, `AWS::MediaConvert::Preset`, `AWS::Route53::RecordSet`, `AWS::SES::ReceiptRuleSet` の各 `Id` 属性が削除。
  - **プロパティの immutable 化・required 化**: `AWS::BedrockAgentCore::PaymentConnector` の `ConnectorType`, `AWS::BedrockAgentCore::PaymentCredentialProvider` の `CredentialProviderVendor`, `AWS::DAX::ParameterGroup` の `Description`, `AWS::DMS::ReplicationTask` の `MigrationType`, `AWS::SSM::Association` の `InstanceId`, `AWS::VpcLattice::ServiceNetwork` の `SharingConfig` などが immutable (作成後変更不可) に。`AWS::Glue::DataQualityRuleset` の `Name` / `TargetTable.DatabaseName` / `TargetTable.TableName` が required に、`Name` は immutable に。
  - **型変更**: `AWS::Chime::AppInstance` / `AppInstanceBot` の `CreatedTimestamp` / `LastUpdatedTimestamp` が `number` → `string` に。`AWS::Glue::DataQualityRuleset` の `Tags` が `json` → `map<string>` に。
  - **プロパティ名変更**: `AWS::Glue::Connection` の複合プロパティ型 `AuthenticationConfigurationInput` / `OAuth2PropertiesInput` がそれぞれ `AuthenticationConfiguration` / `OAuth2Properties` にリネーム。
  - **enum 値の縮小**: `AWS::BedrockAgentCore::CapacityProvider` の `OperatingSystem` (in `LaunchParameters`) が `[LINUX_X86_64, LINUX_ARM64, MAC_ARM64, WINDOWS_X86_64]` から `[LINUX_X86_64, LINUX_ARM64]` に縮小。
  - **プロパティ削除**: `AWS::Route53::RecordSet` の `GeoProximityLocation` プロパティ、および複合型 `GeoProximityLocation` / `Coordinates`。
- **移行方法**: 削除されたリソース・属性を利用していた場合は、AWS 側のサービスドキュメントで代替 API / 代替リソースを確認してください。多くは古い / 内部専用のリソースで、通常のワークロードでは使用されていない想定です。CDK 側で単に L1 の型が消えるので、TypeScript のビルドエラーで検知できます。

## バグ修正

### `core`: `IgnoreStrategy` で除外された外部シンボリックリンクがバリデーションエラーになる問題 ([#38679](https://github.com/aws/aws-cdk/pull/38679))

- `SymlinkFollowMode.BLOCK_EXTERNAL` で外部シンボリックリンクを禁止する `validateInternalSymlinks` が、`IgnoreStrategy` (`.dockerignore` 等) で除外されるファイルまで走査対象にしていたため、「除外されるはずのシンボリックリンク」で誤ってエラーになる false positive がありました。
- 修正では `validateInternalSymlinks` が `IgnoreStrategy` を考慮するようになり、除外対象ファイル配下のシンボリックリンクはバリデーション対象から外れます。あわせて、テスト時の出力挿入で入力側がクリアされないよう内部フローが整理されています。

---

### `core`: テンプレートで循環依存チェックが行われない問題 ([#38712](https://github.com/aws/aws-cdk/pull/38712))

- `cfn-validate` の循環依存 (circular dependency) チェックが `aws-eks` の 1 つのテストが通らないという理由で無効化されており、`cdk synth` 時にはループが検知されず、`cdk deploy` の実行権限を持って初めてクラウド側で失敗するという状態でした。
- 特にエージェント/自動化系ツールが構築する CDK スタックでは循環依存が混入しやすく、オフラインで検知できる価値のほうが高いという判断から、循環依存チェックがグローバルで有効化され、問題の `aws-eks` テストだけが個別に検査除外される形になりました。
- 影響: これまで synth を通過していた「本当は循環依存を含むテンプレート」が今後は synth 時に落ちるようになります。落ちるようになった場合は、リソース間の依存関係を見直してください (これは常にバグだった状態を検知できるようになった、と読むのが正しいです)。

---

### `core`: CloudFormation バリデーションを最新版に更新 ([#38668](https://github.com/aws/aws-cdk/pull/38668))

- 内部の `@aws/cloudformation-validate` を `1.8.0-beta` に更新しました。バグ修正、最新のリソーススキーマ取り込み、性能改善が含まれます。ユーザー側の API は変わりません。

### `eks-v2`: `aws-eks-v2` から L1 コンストラクトを生成・エクスポート ([#37640](https://github.com/aws/aws-cdk/pull/37640))

- `aws-eks-v2` は `aws-eks` を置き換えるために新設されたモジュールですが、`index.ts` が L2 コンストラクトしか export しておらず、`CfnPodIdentityAssociation` などの L1 コンストラクトを利用するには結局 `aws-eks` を併用する必要があり、「自己完結した後継モジュール」という設計目的が満たされていませんでした。
- また、`aws-eks-v2/lib/` 内部の L2 実装も L1 と関連型を `../../aws-eks` から import する状態になっており、置き換え対象への隠れた依存が残っていました。
- 修正内容:
  - `scripts/scope-map.json` に `aws-eks-v2` と `AWS::EKS` namespace を追加し、`eks.generated.ts` を `aws-eks-v2` 用に独立生成 (`eks_v2` / `EKSv2` / `aws_eks_v2` の言語別命名を明示指定して `aws-eks` との衝突を回避)。
  - `aws-eks-v2/lib/index.ts` に `export * from './eks.generated'` を追加し、`CfnAddon` / `CfnCluster` / `CfnFargateProfile` / `CfnIdentityProviderConfig` / `CfnNodegroup` / `CfnAccessEntry` / `CfnCapability` / `CfnPodIdentityAssociation` の 8 種を publicly accessible に。
  - 内部の L2 実装が使う L1 / インタフェースを `../../aws-eks` から `./eks.generated` / `../../interfaces/generated/aws-eks-interfaces.generated` に切り替え。
- 影響: 今後は L1 も含めて `@aws-cdk/aws-eks-v2-alpha` (パッケージ名は変わらず) から一貫して import できます。ユーザーコードに従来 `aws-eks` から import していた `Cfn*` があれば `aws-eks-v2` に置き換え可能です (併用も引き続き可能)。
- 追加修正: 併せて `EKS_USE_NATIVE_OIDC_PROVIDER: false` のまま `AlbController` を使うと `DeprecationError` になっていた 2 つの integration test を `true` に修正 (`OpenIdConnectProvider` (Custom Resource) → `AWS::IAM::OIDCProvider` へ移行)、`securityGroup` (deprecated) → `securityGroups: [sg]` の書き換えも行われています。

## Alpha モジュール

### `glue-alpha`: `DataQualityTargetTable` をリファレンス型化し `clientToken` を削除 ([#38730](https://github.com/aws/aws-cdk/pull/38730)) 【破壊的変更】

**この機能でできること:**

- `DataQualityRuleset` の GA 前 API クリーンアップです。従来の `new DataQualityTargetTable(databaseName, tableName)` は「同型 (`string`) の引数を 2 つ順序で受け取る」形で、しかもモジュール内の L2 と繋がっていない浮いた構造でした。
- 修正で `DataQualityTargetTable` は factory 化され、`DataQualityTargetTable.fromTable(database, table)` / `DataQualityTargetTable.fromTableName(database, tableName)` の 2 つのファクトリで生成する形に統一されました。`database` は `IDatabaseRef` 型を受けるため、`(database, table)` の入れ替えミスが型で防げます。あわせて `IDatabase` が `IDatabaseRef` を extend するようになり (`Database` インスタンス自身が `databaseRef` を公開)、`awslint:interface-extends-ref` の要件を満たします。
- また、`DataQualityRulesetProps.clientToken` は request-level のべき等性トークンで、宣言的な CFN リソース定義に持たせる意味がない (CloudFormation 自身がべき等性を担保する) ため削除されました。従来通り必要な場合は `CfnDataQualityRuleset` の L1 でこのフィールドが引き続き露出しています。

**変更前:**

```typescript
import * as glue from '@aws-cdk/aws-glue-alpha';

declare const database: glue.IDatabase;

new glue.DataQualityRuleset(this, 'Rs', {
  rulesetName: 'my-rs',
  rulesetDqdl: 'Rules = [ ... ]',
  // 生 constructor: (databaseName, tableName) の 2 つ同型引数
  targetTable: new glue.DataQualityTargetTable('my_db', 'my_table'),
  clientToken: 'unique-token', // 削除される
});
```

**変更後:**

```typescript
import * as glue from '@aws-cdk/aws-glue-alpha';

declare const database: glue.IDatabase;
declare const table: glue.ITable;

new glue.DataQualityRuleset(this, 'Rs', {
  rulesetName: 'my-rs',
  rulesetDqdl: 'Rules = [ ... ]',

  // ★ 型付きリファレンスから生成 (database は IDatabaseRef、table は ITable)
  //   database と table を取り違えると型エラーで弾かれる
  targetTable: glue.DataQualityTargetTable.fromTable(database, table),

  // 名前ベースで指定したい場合 (import 済みで型が薄いとき等):
  //   targetTable: glue.DataQualityTargetTable.fromTableName(database, 'my_table'),

  // clientToken は削除。request-level idempotency が必要なら L1 で書く
});
```

**移行方法:**

- `new DataQualityTargetTable(databaseName, tableName)` の呼び出しを、`DataQualityTargetTable.fromTable(database, table)` (L2 の `IDatabase` / `ITable` があるケース) か `DataQualityTargetTable.fromTableName(database, tableName)` (テーブル名だけ持っているケース) に置き換えてください。
- `DataQualityRulesetProps.clientToken` を渡していた箇所は削除。同じ効果が必要な場合は `CfnDataQualityRuleset` L1 に降りて指定してください。

## 破壊的変更まとめ

このリリースには以下の破壊的変更があります (詳細は各セクション参照)。

- **L1 CloudFormation リソースの大規模更新**: 上記「L1 CloudFormation リソース定義の更新」セクション参照。多数のリソース削除・`Id` 属性削除・プロパティの immutable 化 / required 化・型変更・enum 値縮小が含まれます。TypeScript のビルドエラーで検知できるので、まずは `cdk synth` を回して差分を確認してください。
- **Alpha - `glue-alpha`**: `DataQualityTargetTable` の生コンストラクタが削除、`fromTable` / `fromTableName` ファクトリに移行。`IDatabase extends IDatabaseRef` に変更。`DataQualityRulesetProps.clientToken` 削除。

## まとめ

v2.268.0 は、MediaLive の新 L2 alpha 追加、`LaunchTemplate` の `CpuOptions` 対応、CodeBuild Lambda Node.js 24、`BucketDeployment` の Graviton 化といった実利のある機能追加に加え、循環依存チェックの復活・シンボリックリンクバリデーションの厳密化・`aws-eks-v2` の自己完結化など、実運用の「見つかりにくい落とし穴」を潰す修正が入ったリリースです。一方、L1 CloudFormation リソース定義の更新には多数の破壊的変更が含まれるため、対象リソース (特に Glue / DMS / Route53 / DAX 系の `Id` 属性、Chime のタイムスタンプ型、Bedrock AgentCore / Signer / SSM Session など削除リソース) を使っている場合は、アップグレード前に必ず影響範囲を確認してください。
