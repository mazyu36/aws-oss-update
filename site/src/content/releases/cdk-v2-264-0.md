## 概要

AWS CDK v2.264.0 は、CloudWatch のアラームミュートルールを扱う新しい L2 コンストラクトの追加を中心とした機能追加と、`bedrockagentcore` の CloudWatch メトリクスディメンション修正・EBS ボリュームの最大サイズ拡張・Step Functions Tasks の JSONata 対応など、実運用で影響の大きいバグ修正が多数含まれるリリースです。Alpha モジュールでは Glue に新しい `Catalog` L2 が導入され、`mediaconnect-alpha` の `addOutput` API が整理されるなど、いくつかの破壊的変更が含まれる点に注意が必要です。

**リリース:** [v2.264.0](https://github.com/aws/aws-cdk/releases/tag/v2.264.0)

## 新機能

### `cloudwatch`: アラームミュートルール (`AlarmMuteRule`) に対応 ([#37504](https://github.com/aws/aws-cdk/pull/37504))

**この機能でできること:**

- 2026 年 2 月に CloudWatch へ追加された「アラームミュートルール」機能を、L2 コンストラクト `cloudwatch.AlarmMuteRule` で型安全に扱えるようになりました。計画メンテナンスなどのタイミングでアラーム通知を一時的にミュートできます。
- スケジュールを表現するための `cloudwatch.ScheduleExpression` クラスが追加されており、cron 式やワンタイム実行を型付きで指定できます (EventBridge Scheduler の `ScheduleExpression` に着想を得た API 設計)。
- 既存の `IAlarm` に対して `Alarm.addAlarmMuteRule()` を呼び出すユーティリティメソッドも提供されており、既存アラームに手軽にミュートルールを紐付けられます。

**使用例:**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as cloudwatch from 'aws-cdk-lib/aws-cloudwatch';
import { Construct } from 'constructs';

export class AlarmMuteStack extends cdk.Stack {
  constructor(scope: Construct, id: string, props?: cdk.StackProps) {
    super(scope, id, props);

    declare const alarm1: cloudwatch.IAlarm;
    declare const alarm2: cloudwatch.IAlarm;

    // 定期スケジュールでミュートするパターン
    const cronMuteRule = new cloudwatch.AlarmMuteRule(this, 'CronMuteRule', {
      // 対象アラーム (省略可。addAlarm() で後から追加も可能)
      alarms: [alarm1],
      // cron 式でスケジュールを指定。時間帯 (TimeZone) も指定できる
      schedule: cloudwatch.ScheduleExpression.cron({
        minute: '0',
        hour: '0',
        timeZone: cdk.TimeZone.ASIA_TOKYO,
      }),
      // ミュート期間
      duration: cdk.Duration.minutes(30),
    });

    // 作成後にアラームを追加することも可能
    cronMuteRule.addAlarm(alarm2);

    // ワンタイム (一回きり) のスケジュールでミュートするパターン
    new cloudwatch.AlarmMuteRule(this, 'OneTimeMuteRule', {
      alarms: [alarm1],
      // 特定の日時に一度だけ発動 (タイムゾーン省略時は UTC)
      schedule: cloudwatch.ScheduleExpression.at(
        new Date('2026-09-01T00:00:00Z'),
        cdk.TimeZone.ASIA_TOKYO,
      ),
      duration: cdk.Duration.hours(2),
    });

    // 既存の Alarm に対してユーティリティメソッドから紐付ける方法
    alarm1.addAlarmMuteRule('MaintenanceMute', {
      schedule: cloudwatch.ScheduleExpression.cron({
        minute: '0',
        hour: '3',
        weekDay: 'SUN',
      }),
      duration: cdk.Duration.hours(1),
    });
  }
}
```

**ポイント:**

- `alarms` は任意プロパティで、コンストラクタ時に指定しなくても `addAlarm()` で後から追加できます。1 つのミュートルールで複数のアラームをまとめて制御可能です。
- `ScheduleExpression.cron()` は EventBridge の cron 式に近い API で、`minute` / `hour` / `day` / `month` / `weekDay` / `year` などのフィールドと、任意の `timeZone` を受け取ります。
- `ScheduleExpression.at()` は指定した日時に 1 回だけ実行するワンタイムスケジュールで、`Date` オブジェクトとタイムゾーンを受け取ります。
- ミュート中はアラーム通知が抑止されますが、CloudWatch 側のアラーム状態評価そのものは継続して行われます。メンテナンス時間中の状態遷移を後から確認できます。

### L1 CloudFormation リソース定義の更新 ([#38479](https://github.com/aws/aws-cdk/pull/38479), [#38526](https://github.com/aws/aws-cdk/pull/38526))

**この機能でできること:**

- CloudFormation の最新のリソース定義に追従し、新しいプロパティや L1 (`Cfn*`) リソースが CDK から利用できるようになりました。
- 既存の L2 コンストラクトの挙動には直接影響しませんが、新しい CloudFormation リソースを扱う L1 の型やプロパティが増えています。

**ポイント:**

- L2 コンストラクトが未対応の新しい CloudFormation プロパティを利用したい場合は、エスケープハッチ (`node.defaultChild as CfnXxx`) 経由で最新の L1 プロパティを扱えます。

## バグ修正

### `bedrockagentcore`: Gateway メトリクスの CloudWatch ディメンションを修正 ([#38487](https://github.com/aws/aws-cdk/pull/38487)) 【破壊的変更】

- `Gateway` の各メトリクス (`metricInvocations` / `metricThrottles` / `metricSystemErrors` / `metricUserErrors` / `metricLatency` / `metricDuration` / `metricTargetExecutionTime` / `metricTargetType`) が、これまで `{ Resource: <gatewayArn> }` のディメンションのみを出力していたため、AgentCore が実際に `AWS/Bedrock-AgentCore` 名前空間に publish する `{ Operation, Protocol, Resource }` と一致せず、これらのメトリクスヘルパーを使ったアラームがデータを受け取れず常に `INSUFFICIENT_DATA` になっていました。
- 修正後は `{ Operation: 'InvokeGateway', Protocol: <protocolType>, Resource: <gatewayArn> }` の正しいディメンションを出力するようになります。`Protocol` は Gateway のプロトコル設定 (例: `MCP`) から自動的に取得されます。
- 既存の `props.dimensionsMap` によるオーバーライドは引き続き利用可能で、デフォルトディメンションにマージされます。

**影響:** 旧ディメンションに依存していた CloudWatch アラーム・ダッシュボードは新しいディメンションに合わせて更新する必要があります。

---

### `bedrockagentcore`: Runtime メトリクスの CloudWatch ディメンションを修正 ([#38486](https://github.com/aws/aws-cdk/pull/38486)) 【破壊的変更】

- `RuntimeBase` のメトリクスヘルパーも同様に、これまで per-resource メトリクスが `{ Resource: <arn> }`、集約メトリクスが `{ Resource: 'All' }` を出力していたため、AgentCore が publish する実際のメトリクスと一致していませんでした。
- 修正後、per-resource メトリクス (`metricInvocations` / `metricLatency` / `metricThrottles` / `metricSystemErrors` / `metricUserErrors` / `metricTotalErrors` / `metricSessionCount`) は `{ Operation: 'InvokeAgentRuntime', Name: '<runtimeName>::DEFAULT', Resource: <arn> }` を出力します。
- 集約メトリクス (`metricInvocationsAggregated` / `metricSessionsAggregated`) は新設の内部ヘルパーを経由し、`{ AggregateOperation: 'InvokeAgentRuntime' }` を出力します。per-resource のディメンションは自動的に注入されません。

**影響:** 旧ディメンションに依存していた CloudWatch アラーム・ダッシュボードは新しいディメンションに合わせて更新する必要があります。

### `cloudfront`: `minimumProtocolVersion` を証明書なしで指定した場合に警告 ([#37250](https://github.com/aws/aws-cdk/pull/37250))

- カスタム証明書 (`certificate`) を指定していない `Distribution` に対して `minimumProtocolVersion` や `sslSupportMethod` を設定しても、CloudFront デフォルト証明書は固定のセキュリティポリシーを使うため、これらの設定は無視されます。
- これまでは警告なしに設定が反映されない状態でしたが、修正後は synth 時に警告が表示されるようになり、TLS 設定が意図せずデフォルトへフォールバックしている問題に気付きやすくなります。

**使用例 (正しい使い方):**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as acm from 'aws-cdk-lib/aws-certificatemanager';
import * as cloudfront from 'aws-cdk-lib/aws-cloudfront';
import * as origins from 'aws-cdk-lib/aws-cloudfront-origins';

declare const stack: cdk.Stack;
declare const certificate: acm.ICertificate;

// minimumProtocolVersion を効かせるには certificate も併せて指定する必要がある
new cloudfront.Distribution(stack, 'Distribution', {
  defaultBehavior: { origin: new origins.HttpOrigin('example.com') },
  domainNames: ['example.com'],
  certificate,
  minimumProtocolVersion: cloudfront.SecurityPolicyProtocol.TLS_V1_2_2021,
});
```

### `ec2`: EBS gp3 / io2 ボリュームの最大サイズを 64 TiB に対応 ([#37049](https://github.com/aws/aws-cdk/pull/37049))

- AWS 側で gp3 / io2 の EBS ボリュームの最大サイズが 64 TiB (65536 GiB) に拡張されていましたが、CDK のクライアント側バリデーションは 16 TiB (16384 GiB) のままだったため、`Size.gibibytes(25000)` のような正当な指定が synth エラーになっていました。
- 修正により、`ec2.Volume` および `ecs.ServiceManagedVolume` の gp3 / io2 の最大サイズが 65536 GiB に引き上げられ、AWS の実際の制限と一致するようになりました。
- gp2 / io1 / st1 / sc1 / magnetic の各タイプは AWS 側の制限が変わっていないため、従来通り 16 TiB のままです。

**使用例:**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as ec2 from 'aws-cdk-lib/aws-ec2';

declare const stack: cdk.Stack;

// v2.264.0 以降は gp3 / io2 で 16 TiB を超えるサイズを指定可能
new ec2.Volume(stack, 'LargeGp3', {
  availabilityZone: 'us-east-1a',
  size: cdk.Size.gibibytes(25000), // 24.4 TiB。従来は synth エラーになっていた
  volumeType: ec2.EbsDeviceVolumeType.GENERAL_PURPOSE_SSD_GP3,
});
```

### `stepfunctions-tasks`: `CallApiGatewayRestApiEndpoint` の `apiPath` に JSONata 式を指定可能に ([#37738](https://github.com/aws/aws-cdk/pull/37738))

- `CallApiGatewayRestApiEndpoint` に対して `apiPath` を JSONata 式 (`{% ... %}`) で指定すると、`"path" must begin with a "/"` というバリデーションエラーで synth が失敗していました。
- 修正により、`apiPath` が JSONata 式の場合はそれを検知して IAM ポリシー ARN のパス部分を `/*` (ワイルドカード) として構築し、Step Functions のステート定義側では JSONata 式をそのまま渡すようになりました。
- これは既存の `CallApiGatewayHttpApiEndpoint` の挙動と揃える形の修正です。

**使用例:**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as apigateway from 'aws-cdk-lib/aws-apigateway';
import * as sfn from 'aws-cdk-lib/aws-stepfunctions';
import * as tasks from 'aws-cdk-lib/aws-stepfunctions-tasks';

declare const stack: cdk.Stack;
declare const restApi: apigateway.RestApi;

// 入力から動的にパスを組み立てる JSONata 式を apiPath に指定できるようになった
const callApi = new tasks.CallApiGatewayRestApiEndpoint(stack, 'CallApi', {
  api: restApi,
  stageName: 'prod',
  method: tasks.HttpMethod.GET,
  apiPath: '{% "/path/" & $states.input.path_suffix %}',
});
```

**ポイント:**

- IAM ポリシーの ARN は `arn:...:<api-id>/<stage>/<method>/*` の形にスコープされ、必要以上に広い権限は付与されません。
- 静的な文字列で `apiPath` を指定する既存の使い方には影響しません。

## Alpha モジュール

### `glue-alpha`: 新しい `Catalog` L2 コンストラクトを追加 ([#38443](https://github.com/aws/aws-cdk/pull/38443)) 【破壊的変更あり】

**この機能でできること:**

- これまで L1 (`CfnDataCatalogEncryptionSettings`) でしか設定できなかった Glue カタログの暗号化を、新しい `Catalog` L2 コンストラクトから型安全に構成できるようになりました。
- AWS アカウントごとに暗黙的に存在する「アカウント既定カタログ」を、シングルトンとして扱う `Catalog.forAccount(scope)` や、その暗号化設定を行う `Catalog.encryptAccount(scope, ...)` が提供されます。
- 暗号化設定はカタログ作成時に固定される仕様で、`ICatalog` に対する暗号化変更用のミューテーションメソッドは意図的に用意されていません。

**使用例:**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as glue from '@aws-cdk/aws-glue-alpha';
import * as kms from 'aws-cdk-lib/aws-kms';
import { Construct } from 'constructs';

export class GlueCatalogStack extends cdk.Stack {
  constructor(scope: Construct, id: string, props?: cdk.StackProps) {
    super(scope, id, props);

    const key = new kms.Key(this, 'CatalogKey');

    // 名前付きカタログを暗号化設定付きで作成する
    new glue.Catalog(this, 'Catalog', {
      catalogName: 'my-catalog',
      // 保存データの暗号化 (KMS)
      encryptionAtRest: glue.DataCatalogEncryptionAtRest.kms(key),
      // 接続情報のパスワード暗号化
      connectionPasswordEncryption: {
        kmsKey: key,
        returnConnectionPasswordEncrypted: false,
      },
    });

    // アカウント既定カタログ (アカウント ID をそのまま catalogId とするシングルトン) を参照
    const accountCatalog = glue.Catalog.forAccount(this);

    // アカウント既定カタログに暗号化設定を適用 (スタック全体で 1 度だけ、
    // forAccount() や Database の初回利用より前に呼ぶ必要がある)
    glue.Catalog.encryptAccount(this, {
      encryptionAtRest: glue.DataCatalogEncryptionAtRest.kms(key),
    });

    // 既存カタログをインポート (暗号化設定は管理しない純粋な識別子ハンドル)
    const imported = glue.Catalog.fromCatalogArn(this, 'Imported',
      'arn:aws:glue:us-east-1:123456789012:catalog');
  }
}
```

**破壊的変更:**

- `IDatabase.catalogArn` / `IDatabase.catalogId` プロパティが削除され、代わりに型付き `ICatalog` を返す `IDatabase.catalog.catalogArn` / `IDatabase.catalog.catalogId` を経由してアクセスする形に変更されました。
- `IDatabase` のカスタム実装をしている場合は、`catalog` プロパティを実装する必要があります。

**ポイント:**

- `Catalog.encryptAccount()` は同じアカウント既定カタログを対象とする性質上、複数スタックから呼ぶと互いに上書きし合うため、必ず 1 つのスタックで一度だけ呼ぶ必要があります。
- `Catalog.fromCatalogArn` / `Catalog.fromCatalogId` はインポートされたカタログを純粋な識別子ハンドルとして返すため、暗号化設定などの管理は行われません。既存カタログの暗号化を管理したい場合は `CfnDataCatalogEncryptionSettings` を直接使ってください。

### `glue-alpha`: `S3Table` のデータ暗号化を強化 ([#38501](https://github.com/aws/aws-cdk/pull/38501))

**この機能でできること:**

- Glue テーブルが背景にする S3 バケットに対して、AWS Foundational Security Best Practices の S3.5 に準拠した SSL の強制が有効化されました。
- クライアントサイド暗号化を設定した場合でも、クライアント側で実際に暗号化が行われた保証はないため、フォールバックとして S3 マネージド暗号化 (SSE-S3) が保存時暗号化として設定されるようになりました。

**ポイント:**

- 既存のバケット暗号化設定 (SSE-KMS 等) を明示的に指定している場合は、そちらが優先されます。この変更は暗号化未設定のケースでベースラインを引き上げる位置付けです。

### `glue-alpha`: セキュリティ設定の暗号化キーローテーションを有効化 ([#38512](https://github.com/aws/aws-cdk/pull/38512))

- `glue-alpha` の `SecurityConfiguration` で自動生成される KMS キーに対して、AWS セキュリティベストプラクティスに沿ってキーローテーションが有効化されました。
- 既存の CDK ユーザー向けの API 変更はありません。

### `mediaconnect-alpha`: `addOutput` の options 化と VPC インターフェース参照の簡素化 ([#38515](https://github.com/aws/aws-cdk/pull/38515)) 【破壊的変更】

**この機能でできること (および修正内容):**

- `Flow.addOutput()` の第 2 引数が単なる `outputConfig` から `options` オブジェクトに変わり、`flowOutputName` / `description` / `outputStatus` を指定可能になりました。
- Output に VPC インターフェースを紐付ける際、これまでは `VpcInterfaceConfig` オブジェクトを渡す `vpcInterfaceAttachment` プロパティでしたが、代わりに文字列名を受け取る `vpcInterfaceAttachmentName: string` に変わり、クロススタックでの参照がしやすくなりました。
- Router の入出力設定 (`standard` / `failover` / `merge`) に `availabilityZone` を指定できるようになり、`publicNetwork()` の CIDR がオプションとなって「アウトバウンド専用」のインターフェースを表現可能になりました。
- `Flow` のメンテナンスウィンドウ指定は他のリソースと同じ命名規則に揃えられ、`maintenance: { maintenanceDay, maintenanceStartHour }` から `maintenanceConfiguration: { day, time }` へ変更されました。
- これまで `@internal` として非公開だった `FlowOutputBase` / `FlowEntitlementBase` / `FlowSourceBase` / `RouterNetworkInterfaceBase` などのベースクラスが公開され、TypeScript 側から拡張・型参照が可能になりました。

**変更前:**

```typescript
import * as mediaconnect from '@aws-cdk/aws-mediaconnect-alpha';

declare const flow: mediaconnect.Flow;
declare const vpcInterface: mediaconnect.VpcInterface;
declare const output: mediaconnect.FlowOutput;

flow.addOutput('OutputId', output);

flow.maintenance = {
  maintenanceDay: mediaconnect.MaintenanceDay.MONDAY,
  maintenanceStartHour: '02:00',
};
```

**変更後:**

```typescript
import * as mediaconnect from '@aws-cdk/aws-mediaconnect-alpha';

declare const flow: mediaconnect.Flow;
declare const vpcInterface: mediaconnect.VpcInterface;
declare const output: mediaconnect.FlowOutput;

// addOutput は options オブジェクトを受け取るように変更
flow.addOutput('OutputId', {
  output,
  flowOutputName: 'my-output',
  description: '...',
});

// VPC インターフェースは文字列名で参照する (クロススタック対応)
// (Output 定義内などで vpcInterfaceAttachment → vpcInterfaceAttachmentName)
// vpcInterfaceAttachmentName: vpcInterface.name

// maintenance → maintenanceConfiguration にリネームされ、フィールド名も day / time に統一
flow.maintenanceConfiguration = {
  day: mediaconnect.MaintenanceDay.MONDAY,
  time: '02:00',
};
```

**移行方法:**

- `flow.addOutput(id, outputConfig)` としていた呼び出しを `flow.addOutput(id, { output: outputConfig })` に書き換えてください。
- 出力設定にある `vpcInterfaceAttachment: VpcInterfaceConfig` は `vpcInterfaceAttachmentName: string` に置き換え、`myVpcInterface.name` を渡すようにしてください。
- `maintenance: { maintenanceDay, maintenanceStartHour }` を `maintenanceConfiguration: { day, time }` にリネームしてください。

## まとめ

v2.264.0 は、CloudWatch のアラームミュートルール対応という利用価値の高い新機能に加え、`bedrockagentcore` のメトリクスディメンション修正・EBS gp3 / io2 の最大サイズ拡張・Step Functions Tasks の JSONata 対応といった、実運用で「動いていなかった」ケースを解消する重要な修正が並ぶリリースです。Alpha モジュールでは Glue の `Catalog` L2 が新設されて暗号化設定が扱いやすくなる一方、`mediaconnect-alpha` の `addOutput` 周辺 API が整理されているため、これらを利用している場合はアップグレード時に移行対応を確認してください。
