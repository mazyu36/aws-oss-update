## 概要

AWS CDK v2.266.0 は、EKS `Cluster` L2 への `controlPlaneScalingConfig` 追加や L1 CFN リソース定義更新といった機能追加に加え、EC2 dual-stack VPC で IPv6 デフォルトルートがゲートウェイアタッチ前に作られてしまう問題や、SNS のオプトインリージョン跨ぎサブスクリプションでメッセージが黙って落ちる問題といった実害の大きいバグ修正を含むリリースです。Alpha モジュール側では `glue-alpha` に GA 前 API レビューを反映した多数の破壊的変更が入っており、該当モジュールを利用中のユーザーはアップグレード時の API 差分を必ず確認してください。

**リリース:** [v2.266.0](https://github.com/aws/aws-cdk/releases/tag/v2.266.0)

## 新機能

### `eks`: `Cluster` に `controlPlaneScalingConfig` を追加 ([#36863](https://github.com/aws/aws-cdk/pull/36863))

**この機能でできること:**

- EKS の Cluster コントロールプレーンをスケールする際の設定 (`controlPlaneScalingConfig`) を、L1 (`CfnCluster`) だけでなく L2 の `Cluster` コンストラクトからも指定できるようになりました。
- これまで L1 側にのみあったパススルー設定が L2 に揃うため、`CfnCluster` へのエスケープ無しで通常の L2 API のまま指定可能です。

**使用例:**

```typescript
import * as cdk from 'aws-cdk-lib';
import * as ec2 from 'aws-cdk-lib/aws-ec2';
import * as eks from 'aws-cdk-lib/aws-eks';
import { KubectlV32Layer } from '@aws-cdk/lambda-layer-kubectl-v32';
import { Construct } from 'constructs';

export class EksClusterStack extends cdk.Stack {
  constructor(scope: Construct, id: string, props?: cdk.StackProps) {
    super(scope, id, props);

    const vpc = new ec2.Vpc(this, 'Vpc');

    new eks.Cluster(this, 'Cluster', {
      vpc,
      version: eks.KubernetesVersion.V1_32,
      kubectlLayer: new KubectlV32Layer(this, 'KubectlLayer'),
      // コントロールプレーンのスケーリング設定 (L1 の cfn プロパティを L2 でも受け付け)
      controlPlaneScalingConfig: {
        // ゾーンあたりのコントロールプレーンレプリカ最小台数 (省略可)
        minZonalReplicaCount: 3,
      },
    });
  }
}
```

**ポイント:**

- 内部的には L1 の `cfnCluster` の同名プロパティにそのまま渡されるパススルーであり、CloudFormation リソース側のバリデーションに従います。
- 従来 L1 にエスケープしていたコードは、この L2 プロパティに置き換えることで L2 API に統一できます。

### L1 CloudFormation リソース定義の更新 ([#38578](https://github.com/aws/aws-cdk/pull/38578))

**この機能でできること:**

- 最新の CloudFormation リソーススペックを取り込み、`CfnXxx` (L1) リソースのプロパティ・型定義が更新されました。新規追加された AWS サービスのプロパティも L1 から利用可能になります。
- L2 の API 差分は含まれず、L1 のみへのアップデートですが、最新のサービス機能を早期に利用したい場合はこのバージョンで L1 経由で扱えます。

**ポイント:**

- 各 L2 コンストラクトの新プロパティ対応は今後のリリースで順次追加されるため、まだ L2 対応されていない新プロパティは `CfnXxx` (L1) 経由で指定してください。

## バグ修正

### `ec2`: IPv6 デフォルトルートに VPCGatewayAttachment への `DependsOn` を追加 ([#37893](https://github.com/aws/aws-cdk/pull/37893))

- IPv4 側の `addDefaultInternetRoute` は VPCGatewayAttachment への `DependsOn` を持っており、CloudFormation が Internet Gateway のアタッチ完了を待ってから `0.0.0.0/0` ルートを作っていました。一方、IPv6 側の `addIpv6DefaultInternetRoute` にはこの依存関係が抜けており、`::/0` ルートが IGW アタッチ前に作られてしまい `The gateway ID 'igw-xxx' does not exist` エラーでデプロイが失敗するケースがありました。
- 修正により、`addIpv6DefaultInternetRoute` に任意引数 `gatewayAttachment?: IDependable` が追加され、内部呼び出し側ではこれを渡すことで IPv4 側と同じ `DependsOn` が付与されるようになりました。既存の外部呼び出し (ゲートウェイ ID のみで呼んでいるコード) は引数がオプショナルのため後方互換で動作します。
- 影響を受けるのは dual-stack VPC を CDK で構築しているユーザーで、修正後は再現していたゲートウェイ未存在エラーが解消されます。

### `sns-subscriptions`: オプトインリージョンを含む SQS サブスクリプションでリージョナライズドサービスプリンシパルを使用 ([#38339](https://github.com/aws/aws-cdk/pull/38339))

- `SqsSubscription` および `LambdaSubscription` がキュー / 関数側に付与するポリシーで、常にグローバルな `sns.amazonaws.com` サービスプリンシパルが使われていました。しかし [SNS のクロスリージョン配信ドキュメント](https://docs.aws.amazon.com/sns/latest/dg/sns-cross-region-delivery.html) の通り、オプトインリージョンが関わるサブスクリプションではリージョナライズドサービスプリンシパル (`sns.<region>.amazonaws.com`) が必要で、そうしないとメッセージが黙って落ちるという問題がありました。
- 修正により、トピック側とサブスクライバー側のリージョンを見て以下のように自動でプリンシパルを選択するようになりました。
  - デフォルトリージョン → オプトインリージョン: `sns.<subscriber-region>.amazonaws.com`
  - オプトインリージョン → デフォルトリージョン: `sns.<topic-region>.amazonaws.com`
  - オプトインリージョン → オプトインリージョン: `sns.<subscriber-region>.amazonaws.com`
  - デフォルト → デフォルト: 従来通り `sns.amazonaws.com`
  - トークン (リージョン未解決): 安全側の既定として `sns.amazonaws.com`
- オプトインリージョン (例: `ap-southeast-4`) を跨いだ SNS → SQS / Lambda を CDK で組んでいたユーザーは、本バージョン以降で自動的に正しいプリンシパルが設定されるため、コード変更は不要でメッセージ配信が復旧します。

## Alpha モジュール

### `glue-alpha`: `SecurityConfiguration` の暗号化をファクトリー型に変更 ([#38586](https://github.com/aws/aws-cdk/pull/38586)) 【破壊的変更】

**この機能でできること:**

- `s3Encryption` / `cloudWatchEncryption` / `jobBookmarksEncryption` の 3 つの暗号化ブロックが `{ mode, kmsKey? }` 形式のオブジェクトリテラルからファクトリークラス方式に置き換えられました。以前は S3 で `{ mode: S3_MANAGED, kmsKey }` のような不正な組み合わせが指定でき、`kmsKey` が黙って捨てられて SSE-S3 が適用される、というセキュリティ面で問題のある silent failure が起こり得ました。
- ファクトリー側では `S3Encryption.s3Managed()` は KMS キーを受け取らない設計になっており、SSE-S3 + KMS キーという不正な組み合わせ自体がコンパイル時に表現不可能になっています。CloudWatch / JobBookmarks 側は `mode` が実質単一値だったため、その enum も削除されました (`CloudWatchEncryptionMode` / `JobBookmarksEncryptionMode` が撤去。`S3EncryptionMode` は残置)。

**変更前:**

```typescript
import * as glue from '@aws-cdk/aws-glue-alpha';

new glue.SecurityConfiguration(this, 'Sc', {
  s3Encryption: {
    mode: glue.S3EncryptionMode.KMS,
    kmsKey: myKey,
  },
  cloudWatchEncryption: {
    mode: glue.CloudWatchEncryptionMode.KMS, // ← 削除される enum
    kmsKey: myKey,
  },
  jobBookmarksEncryption: {
    mode: glue.JobBookmarksEncryptionMode.CLIENT_SIDE_KMS, // ← 削除される enum
    kmsKey: myKey,
  },
});
```

**変更後:**

```typescript
import * as glue from '@aws-cdk/aws-glue-alpha';

new glue.SecurityConfiguration(this, 'Sc', {
  // S3: SSE-S3 は kmsKey を受け取らない (silent-drop が不可能に)
  s3Encryption: glue.S3Encryption.kms(myKey),
  // または glue.S3Encryption.s3Managed()

  // CloudWatch / JobBookmarks は mode がファクトリー名に埋め込まれる
  cloudWatchEncryption: glue.CloudWatchEncryption.kms(myKey),
  jobBookmarksEncryption: glue.JobBookmarksEncryption.clientSideKms(myKey),
});
```

**移行方法:**

- 旧オブジェクトリテラルを対応するファクトリーメソッドに置き換えてください。`kms(key?)` は引数省略時に KMS キーを自動生成する挙動が維持されています。合成後のテンプレートは正当な入力に対しては同一です。

### `glue-alpha`: `workerType` / `numberOfWorkers` を `workerConfiguration` にまとめて必須化 ([#38576](https://github.com/aws/aws-cdk/pull/38576)) 【破壊的変更】

**この機能でできること:**

- Spark ジョブ用の `workerType` と `numberOfWorkers` は本来ペアで指定する必要がありましたが、これまでは基底 `JobProps` 上の 2 つの独立オプショナルプロパティとして定義されていました。そのため片方だけ指定された不正状態が synth 時まで検出できず、また `PythonShellJob` はこれらを黙って無視、`RayJob` は `workerType` の値を実行時に弾く、といった一貫性の欠けた実装になっていました。
- 修正により、Spark ジョブ (`SparkJobProps` を継承する各種) では `workerConfiguration: { workerType, numberOfWorkers }` 値オブジェクトとしてペアで受け取り、コンパイル時に片方だけの状態を作れなくなりました。`PythonShellJob` はプロパティ自体が撤去 (`maxCapacity` で DPU 指定)、`RayJob` は `workerType` を撤去 (`Z.2X` 固定) し、`numberOfWorkers` のみ受け付ける形になりました。

**変更前:**

```typescript
import * as glue from '@aws-cdk/aws-glue-alpha';

new glue.PySparkEtlJob(this, 'Job', {
  role,
  script: glue.Code.fromAsset('script.py'),
  workerType: glue.WorkerType.G_1X,
  numberOfWorkers: 5,
});
```

**変更後:**

```typescript
import * as glue from '@aws-cdk/aws-glue-alpha';

new glue.PySparkEtlJob(this, 'Job', {
  role,
  script: glue.Code.fromAsset('script.py'),
  // Spark ジョブでは 2 プロパティをペアで指定
  workerConfiguration: {
    workerType: glue.WorkerType.G_1X,
    numberOfWorkers: 5,
  },
});
```

**移行方法:**

- Spark ジョブ (`PySparkEtlJob` / `ScalaSparkEtlJob` / `*FlexEtlJob` / `*StreamingJob` など) は 2 プロパティを `workerConfiguration` 配下に移動してください。
- `PythonShellJob` は `workerType` / `numberOfWorkers` を削除し、DPU サイズを `maxCapacity` で指定してください。
- `RayJob` は `workerType` を削除 (`Z.2X` 固定) し、`numberOfWorkers` はトップレベルのまま利用可能です。

### `glue-alpha`: `DataQualityRuleset` の DQDL を型付き値オブジェクトに ([#38587](https://github.com/aws/aws-cdk/pull/38587)) 【破壊的変更】

**この機能でできること:**

- 従来 `DataQualityRulesetProps.rulesetDqdl: string` として、L1 に素通しの文字列で受け取っていた DQDL (Data Quality Definition Language) が、`Dqdl` 値オブジェクトを介して型付きで受け取る API に変更されました。
- Glue 側の DQDL のバリデーションはデプロイ時に行われる点や、レンダリング結果の文字列は不変で合成出力に差分は無い点は変わりません。今後 DQDL を型付きの個別ルールとしてモデル化する拡張余地を残しつつ、当面は `Dqdl.fromString(...)` のエスケープハッチのみを提供する形です。

**変更前:**

```typescript
import * as glue from '@aws-cdk/aws-glue-alpha';

new glue.DataQualityRuleset(this, 'Ruleset', {
  rulesetName: 'my_ruleset',
  targetTable: new glue.DataQualityTargetTable(dbName, tableName),
  rulesetDqdl: 'Rules = [ ColumnValues "id" > 100 ]',
});
```

**変更後:**

```typescript
import * as glue from '@aws-cdk/aws-glue-alpha';

new glue.DataQualityRuleset(this, 'Ruleset', {
  rulesetName: 'my_ruleset',
  targetTable: new glue.DataQualityTargetTable(dbName, tableName),
  dqdl: glue.Dqdl.fromString('Rules = [ ColumnValues "id" > 100 ]'),
});
```

**移行方法:**

- `rulesetDqdl: '...'` を `dqdl: glue.Dqdl.fromString('...')` に置き換えてください。文字列の中身は変更不要です。

### `glue-alpha`: 型付き `hasEncryptedData` プロパティ追加 ([#38511](https://github.com/aws/aws-cdk/pull/38511)) 【破壊的変更】

**この機能でできること:**

- Glue テーブルのストレージディスクリプタが持つ `has_encrypted_data` (Athena がクライアントサイド暗号化データを扱うためのフラグ) は、これまで `S3Table` / `ExternalTable` で `true` にハードコーディングされ、上書きするには自由記述の `parameters` プロパティに `has_encrypted_data` を混ぜ込むしかありませんでした。
- `TableBaseProps` に型安全な `hasEncryptedData: boolean` プロパティが追加され、これが唯一の指定手段になりました。あわせて `parameters` に `has_encrypted_data` を突っ込むと矛盾または (トークンで) 判定不能な場合に synth 時に例外がスローされるようになっています。

**変更前:**

```typescript
import * as glue from '@aws-cdk/aws-glue-alpha';

new glue.S3Table(this, 'Table', {
  database,
  columns: [{ name: 'id', type: glue.Schema.INTEGER }],
  dataFormat: glue.DataFormat.JSON,
  // parameters 経由の incidental な指定 (もう受け付けない)
  parameters: {
    has_encrypted_data: 'false',
  },
});
```

**変更後:**

```typescript
import * as glue from '@aws-cdk/aws-glue-alpha';

new glue.S3Table(this, 'Table', {
  database,
  columns: [{ name: 'id', type: glue.Schema.INTEGER }],
  dataFormat: glue.DataFormat.JSON,
  // 型付きプロパティで明示的に指定
  hasEncryptedData: false,
});
```

**移行方法:**

- `parameters.has_encrypted_data` を使っていた場合は `hasEncryptedData` プロパティに移してください。値がハードコード `true` に依存していた場合は、そのままの挙動を維持したければ `hasEncryptedData: true` を明示指定するのが安全です。

### `glue-alpha`: `SparkJobProps.enableMetrics` 削除 ([#38575](https://github.com/aws/aws-cdk/pull/38575)) 【破壊的変更】

**この機能でできること:**

- 合わせて Job Run キューイングが有効な際に `maxRetries` が指定されていると、CloudFormation デプロイ時に Glue 側でエラーになるケースがあるため、synth 時に警告を出すようになりました。
- 加えて、どこからも参照されておらず、意味的にも `SparkJobProps.enableMetrics` と重複していた `enableProfilingMetrics` プロパティが削除されました。あわせて `SparkJobProps.enableMetrics` 自体も撤去されており、これらを使っていたコードはコンパイルエラーになりますが、元々ランタイム挙動を持たないデッドプロパティのため機能差はありません。

**移行方法:**

- `enableMetrics` / `enableProfilingMetrics` を渡している箇所は削除してください。挙動差はありません。
- ジョブ実行キューイング (`jobRunQueuingEnabled: true`) と `maxRetries` を併用しているコードでは、synth 時に警告が出るようになるため、ログに注意してください。

### `glue-alpha`: `OutputFormat.AVRO` / `OutputFormat.ORC` の型を修正 ([#38593](https://github.com/aws/aws-cdk/pull/38593)) 【破壊的変更】

- `OutputFormat.AVRO` と `OutputFormat.ORC` が実装バグにより `InputFormat` のインスタンスとして構築されていました。TypeScript では両クラスが構造的に一致するためコンパイルは通っていましたが、jsii の他言語 (Python / Java / .NET) では意図した使い方 (`OutputFormat` として利用する) が破綻していました。
- 本修正により両者は正しく `OutputFormat` インスタンスとなりました。合成される Hadoop クラス名文字列は変更されないため CloudFormation テンプレート差分はありません。あわせて `S3Table` / `ExternalTable` の `renderColumns` 型が `Array<Column | Column>` から `Column[]` に、`Database.locationUri` が `readonly` に整理されています。
- バグに依存して `InputFormat x = OutputFormat.AVRO;` のような書き方をしていたコード (jsii 他言語) はコンパイルエラーになりますが、本来の使い方であれば逆に他言語からも正しく動くようになります。

---

### `glue-alpha`: Job Run キューイング有効時の `maxRetries` に警告 ([#38575](https://github.com/aws/aws-cdk/pull/38575))

- Glue ジョブで Job Run キューイング (`jobRunQueuingEnabled: true`) を有効化している状態で `maxRetries > 0` を指定すると、Glue 側の仕様で組み合わせが不整合となりデプロイに失敗し得るため、synth 時に警告を出すようになりました。
- 挙動を変更するのではなく警告のみのため、既存コードには影響しません。警告が出た場合は `maxRetries` の指定を見直してください。

---

### `glue-alpha`: 構造体型文字列からコメントを除外 ([#38008](https://github.com/aws/aws-cdk/pull/38008))

- `Schema.struct()` が構造体フィールドの `comment` を、生成する Glue の型文字列 (`inputString`) 内に `COMMENT '...'` として埋め込んでいましたが、Glue / Athena はネストされた型定義内での `COMMENT` をサポートしていないため、ネストスキーマで型文字列が使えなくなる問題がありました。
- 修正により、`Schema.struct()` はネスト型文字列にコメントを含めないようになりました。トップレベル `Column` の `comment` は Glue の別プロパティ (`Comment`) として表現されるため、こちらの機能は従来通り利用可能です。

---

### `mediapackagev2-alpha`: MediaPackageV2 に `GetChannel` 権限を付与 ([#38582](https://github.com/aws/aws-cdk/pull/38582))

- `mediapackagev2-alpha` の grant 定義に `GetChannel` API に対する権限が欠けていたため、`.grants()` 経由で `GetChannel` を呼び出そうとした際にアクセス拒否になるケースがありました。
- 修正により `grants.json` に `GetChannel` が追加され、対応する grant メソッド経由で正しく権限が付与されるようになりました。

## まとめ

v2.266.0 は、EKS `Cluster` L2 の `controlPlaneScalingConfig` 追加という stable 側の機能追加に加え、dual-stack VPC やオプトインリージョン SNS といった実運用で踏みがちなバグを 2 つ修正した、地味だが実害の大きい修正が中心のリリースです。Alpha 側では `glue-alpha` の GA 前 API レビューを反映した破壊的変更が多数含まれるため、`glue-alpha` を利用している場合はアップグレード時に暗号化 API / `workerConfiguration` / `Dqdl` / `hasEncryptedData` / `OutputFormat` の 5 点を必ず差分確認してください。
