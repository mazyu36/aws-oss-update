## 概要

このリリースでは、`aws-glue` L2 コンストラクトが alpha から stable モジュールに昇格しました。また Lambda で S3 Files ファイルシステムマウントの `DirectS3Read` プロパティを L2 で設定できるようになり、core モジュールには synth 時に CloudFormation テンプレートを検証する Rego ベースのデフォルトバリデーションルールが導入されました。加えて WebSocket API、S3 レプリケーションメトリクスなどのバグ修正、および L1 CloudFormation リソース定義の更新に伴う破壊的変更が含まれています。

**リリース:** [v2.270.0](https://github.com/aws/aws-cdk/releases/tag/v2.270.0)

## 新機能

### Glue モジュールが stable 化 ([#38799](https://github.com/aws/aws-cdk/pull/38799))

**この機能でできること:**
- これまで `@aws-cdk/aws-glue-alpha` にのみ存在していた Glue L2 コンストラクト（`Job`、`Database`、`Table`、`SecurityConfiguration`、`Connection`、`Workflow`、`Trigger` など）が `aws-cdk-lib/aws-glue` に昇格し、alpha 依存なしで利用できるようになりました。
- GA 準備の過程で 18 件の破壊的変更が加えられ、暗号化・セキュリティ、Job 設定、ワークフロートリガーなどが整理されています。

**使用例:**

```typescript
import * as glue from 'aws-cdk-lib/aws-glue';
import * as s3 from 'aws-cdk-lib/aws-s3';

// Database と Table の作成
const database = new glue.Database(this, 'MyDatabase', {
  databaseName: 'my_database',
});

const bucket = new s3.Bucket(this, 'DataBucket');

// Glue Job の作成
// workerType と numberOfWorkers は workerConfiguration にペア化された
new glue.Job(this, 'MyJob', {
  executable: glue.JobExecutable.pythonEtl({
    glueVersion: glue.GlueVersion.V5_0, // Flex Job のデフォルトは Glue 5.0
    pythonVersion: glue.PythonVersion.THREE,
    script: glue.Code.fromBucket(bucket, 'scripts/my-script.py'),
  }),
  // 旧: workerType + numberOfWorkers を個別に指定
  // 新: workerConfiguration にまとめて指定
  workerConfiguration: glue.WorkerConfiguration.g1X(10),
  // defaultArguments は管理引数・予約引数を拒否するように変更された
  defaultArguments: {
    '--custom-arg': 'value',
  },
});
```

**ポイント:**
- alpha からの主な破壊的変更（既存の alpha ユーザー向け）:
  - **暗号化とセキュリティ**: `SecurityConfiguration` / `S3Table` の暗号化がバリューオブジェクト/ファクトリとしてモデル化され、新しく `Catalog` L2 と `ICatalog` が追加されました。`hasEncryptedData` は型付き、KMS 入力は `IKeyRef` になります。
  - **Job**: `defaultArguments` は Glue が予約する引数を受け付けなくなり、`workerType` + `numberOfWorkers` が `workerConfiguration` にペア化されました。Flex Job のデフォルトは Glue 5.0 で、`enableMetrics` は削除されています。
  - **Connection**: VPC 配置は `ConnectionNetwork` 経由で指定します。
  - **Workflow triggers**: `Action` / `Condition` ファクトリに刷新され、スケジュールトリガーが統合、参照戻り値の型が整備されました。
  - **RayJob は昇格対象外**: Glue for Ray が新規顧客受付を停止したため、`RayJob` は stable には移行しません。
  - **デプロイ時の注意**: パーティションインデックスのカスタムリソース種別が `Custom::AWS` から `Custom::GluePartitionIndex` に変わり、初回更新時に置換が発生します（データロスはありません）。

### Lambda の S3 Files マウントで DirectS3Read をサポート ([#38752](https://github.com/aws/aws-cdk/pull/38752))

**この機能でできること:**
- Lambda の S3 Files ファイルシステムマウントで、対象読み取りを S3 から直接ストリームするかどうかを制御する `DirectS3Read` を L2 から設定できるようになりました。従来は L1 エスケープハッチが必要でした。
- 新しく `DirectS3ReadMode` enum（`ENABLED` / `DISABLED` / `AUTO`）と `S3FilesOptions` インターフェースが追加され、`FileSystem.fromS3FilesAccessPoint()` の第 3 引数として指定できます。

**使用例:**

```typescript
import * as lambda from 'aws-cdk-lib/aws-lambda';
import * as s3 from 'aws-cdk-lib/aws-s3';

declare const accessPoint: s3.CfnAccessPoint;

new lambda.Function(this, 'MyFunction', {
  runtime: lambda.Runtime.NODEJS_20_X,
  handler: 'index.handler',
  code: lambda.Code.fromInline('exports.handler = async () => {};'),
  filesystem: lambda.FileSystem.fromS3FilesAccessPoint(
    accessPoint,
    '/mnt/s3', // マウントパス
    {
      // ENABLED: 直接読み取りを常に有効化（高スループット）
      // DISABLED: 常に S3 Files マウントターゲット経由
      // AUTO: メモリ 512 MB 以上の関数で自動的に有効化
      directS3Read: lambda.DirectS3ReadMode.ENABLED,
    },
  ),
});
```

**ポイント:**
- `AUTO` モードはメモリが 512 MB 以上に設定された関数で直接読み取りを有効化します（[Lambda ドキュメント](https://docs.aws.amazon.com/lambda/latest/dg/configuration-filesystem-s3files.html) 参照）。
- 直接読み取りには関数の実行ロールに `s3:GetObject` / `s3:GetObjectVersion` の権限が必要ですが、権限付与はユーザー側の責任範囲であり、このコンストラクトでは自動付与されません。
- `directS3Read` を省略した場合、L1 テンプレートに `S3FilesConfig` プロパティは出力されません（従来の動作を維持）。

### CloudFormation バリデーションルール（Rego）を core にデフォルトで同梱 ([#38448](https://github.com/aws/aws-cdk/pull/38448))

**この機能でできること:**
- `CloudFormationValidatePlugin` が自動登録されるデフォルトインスタンスで、CDK 同梱の Rego ルールが synth のたびに自動的に実行されるようになりました。
- 初回のルールセットとして `aws-gamelift-alpha` 向けの `gamelift-fleet.rego`（`CDK-GameLift-001` ～ `CDK-GameLift-007`）が提供されます。inverted port range、`locationCapacity` の min/max 逸脱、`SIMPLE` ルーティングに terminal message を混在させたエイリアスなどをスキーマレベルではなく synth 時に検出できます。
- L2 コンストラクト単体では検出できないクロスリソースの制約（例: `AWS::GameLift::Fleet` の `LaunchPath` が参照先 `AWS::GameLift::Build` の `OperatingSystem` と整合しているか）を、`Ref` グラフを辿って検証します。

**使用例:**

```typescript
// synth 時にデフォルトルールが自動実行される
// 誤った設定の GameLift Fleet を作成した例
import * as gamelift from 'aws-cdk-lib/aws-gamelift';

new gamelift.CfnFleet(this, 'GameFleet', {
  name: 'game-fleet',
  buildId: 'build-xxx',
  ec2InstanceType: 'c5.large',
  ec2InboundPermissions: [
    // FromPort > ToPort（逆順の port range）→ CDK-GameLift-001 が検出
    { fromPort: 7877, toPort: 7777, ipRange: '0.0.0.0/0', protocol: 'UDP' },
  ],
  locations: [
    {
      location: 'us-east-1',
      // desiredEc2Instances が minSize/maxSize の範囲外 → CDK-GameLift-003 が検出
      locationCapacity: { desiredEc2Instances: 10, minSize: 1, maxSize: 4 },
    },
  ],
  runtimeConfiguration: {
    serverProcesses: [
      { launchPath: '/local/game/server', concurrentExecutions: 1 },
    ],
  },
});
```

`cdk synth` 実行時の出力例:

```log
ERROR EC2InboundPermissions.0.FromPort: Ingress rule port range is inverted:
      FromPort 7877 is greater than ToPort 7777 (CloudFormation Validate)
   Acknowledge with 'CloudFormation-Validate::CDK-GameLift-001'

ERROR Locations.0.LocationCapacity.DesiredEC2Instances: Location capacity
      DesiredEC2Instances 10 is outside the range [MinSize 1, MaxSize 4]
      (CloudFormation Validate)
   Acknowledge with 'CloudFormation-Validate::CDK-GameLift-003'
```

**ポイント:**
- デフォルトルールは警告として表示され、synth 自体は失敗しません。厳格に扱いたい場合はフィーチャーフラグ `@aws-cdk/core:validateAgainstDefaultRules` を有効化してください。
- 個別ルールを許容したい場合は、メッセージに表示される ID（例: `CloudFormation-Validate::CDK-GameLift-001`）を `Annotations.of(scope).acknowledgeWarning()` で明示的に許容できます。
- Rego ルールはスキーマレベルの検証を超え、`Ref` によるリソース間依存や複数フィールドをまたぐ不変条件も表現できるため、実際のデプロイ失敗（誤設定による起動失敗など）を synth 時点で先取り検出できます。

## バグ修正

### WebSocket API で 1 つの Lambda 統合を複数ルートで共有した際に Lambda 権限が欠落する問題を修正 ([#38154](https://github.com/aws/aws-cdk/pull/38154))

- 単一の `WebSocketLambdaIntegration` インスタンスを `$connect` / `$disconnect` / `$default` など複数ルートで共有した場合、これまでは最初のルートにしか `AWS::Lambda::Permission` が作成されず、実行時に `API_CONFIGURATION_ERROR` が発生していました。
- 原因は `WebSocketRouteIntegration._bindToRoute()` が bind 結果をキャッシュし、2 つ目以降のルートで `bind()` を呼ばなかったため、権限作成の副作用が実行されていなかったことです。
- 今回の修正で `bind()` はルートごとに呼び出されるようになり（共有される `AWS::ApiGatewayV2::Integration` リソース自体は 1 回のみ作成）、各ルート固有スコープで `AWS::Lambda::Permission` が生成されるようになりました。

**修正後の使用例:**

```typescript
import * as apigwv2 from 'aws-cdk-lib/aws-apigatewayv2';
import * as integrations from 'aws-cdk-lib/aws-apigatewayv2-integrations';
import * as lambda from 'aws-cdk-lib/aws-lambda';

declare const fn: lambda.Function;

// 1 つの integration を複数ルートで共有
const integration = new integrations.WebSocketLambdaIntegration('Integration', fn);

new apigwv2.WebSocketApi(this, 'Api', {
  connectRouteOptions: { integration },
  disconnectRouteOptions: { integration }, // 権限が正しく作成される
  defaultRouteOptions: { integration },    // 権限が正しく作成される
});
```

### S3 Bucket のレプリケーションメトリクスが RTC なしで有効化できない問題を修正 ([#35929](https://github.com/aws/aws-cdk/pull/35929))

- 従来、`ReplicationRule` のメトリクスを有効化すると、内部で `eventThreshold` が常に付与されるため、Replication Time Control（RTC）も同時に必須となっていました。
- 実際の S3 API では、レプリケーションメトリクスは `Status: Enabled` のみを設定して RTC 非有効のまま独立して利用できます。今回の修正で L2 の挙動が API と一致し、RTC を伴わずにメトリクスのみを有効化できるようになりました（後方互換の非破壊的な変更）。

### `Annotations.addWarningV2` を acknowledge するには従来フィーチャーフラグが必要だった問題を修正 ([#38772](https://github.com/aws/aws-cdk/pull/38772))

- `Annotations.of(scope).addWarningV2('<id>')` で追加した警告は、`Validations.of(scope).acknowledge({ id: 'Annotation::<id>' })` で確認できることが想定されていましたが、annotation が validation report に書き出されない場合、CLI が read 時に construct metadata とマージしてしまい acknowledge が効かない状態でした。
- 今回の修正で construct metadata から annotation を正しくフィルタリングするようになり、フィーチャーフラグ有無に依存せず acknowledge が機能するようになりました。

## 破壊的変更

### L1 CloudFormation リソース定義の更新 ([#38823](https://github.com/aws/aws-cdk/pull/38823))

L1 リソースは公開 CloudFormation Resource Schemas から自動生成されており、実際の CloudFormation の状態を正確に反映するために互換性のない変更が入ることがあります。今回のリリースでは以下の変更が含まれます。

- **aws-codecommit**: `AWS::CodeCommit::Repository` の `Id` 属性が削除されました。
- **aws-config**: `AWS::Config::DeliveryChannel` の `DeliveryFrequency` プロパティが、`One_Hour` / `Three_Hours` / `Six_Hours` / `Twelve_Hours` / `TwentyFour_Hours` のいずれかを取る enum に絞り込まれました。
- **aws-dms**: `AWS::DMS::ReplicationTask` の `Id` 属性が削除されました。

**変更前:**

```typescript
import * as codecommit from 'aws-cdk-lib/aws-codecommit';
import * as config from 'aws-cdk-lib/aws-config';

declare const repo: codecommit.CfnRepository;
const repoId = repo.attrId; // 削除された属性

const channel = new config.CfnDeliveryChannel(this, 'Ch', {
  s3BucketName: 'bucket',
  configSnapshotDeliveryProperties: {
    deliveryFrequency: 'CustomFrequency', // enum 外の値も許容されていた
  },
});
```

**変更後:**

```typescript
import * as codecommit from 'aws-cdk-lib/aws-codecommit';
import * as config from 'aws-cdk-lib/aws-config';

declare const repo: codecommit.CfnRepository;
// repo.attrId は使用不可。代わりに attrArn または attrName を利用
const repoArn = repo.attrArn;

const channel = new config.CfnDeliveryChannel(this, 'Ch', {
  s3BucketName: 'bucket',
  configSnapshotDeliveryProperties: {
    // 有効値: One_Hour | Three_Hours | Six_Hours | Twelve_Hours | TwentyFour_Hours
    deliveryFrequency: 'TwentyFour_Hours',
  },
});
```

**移行方法:**
- `AWS::CodeCommit::Repository` および `AWS::DMS::ReplicationTask` の `attrId` を参照しているコードは、代替属性（例: ARN や Name）に置き換えてください。
- `AWS::Config::DeliveryChannel` の `deliveryFrequency` は enum 値のいずれかを指定してください（従来から実際に受け付けられていた値は同じセットです）。

## まとめ

`aws-glue` モジュールの stable 化、Lambda の `DirectS3Read` サポート、core モジュールの Rego ベースデフォルトバリデーションルール導入と、実運用でのミス防止に寄与する機能が多く含まれるリリースです。L1 リソース定義の破壊的変更も含まれるため、CodeCommit / Config / DMS を利用しているスタックはアップグレード時に注意してください。
