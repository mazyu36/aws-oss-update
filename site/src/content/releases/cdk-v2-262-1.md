## 概要

このリリースは、v2.262.0 で追加された組み込み CloudFormation テンプレート検証プラグイン (`CloudFormationValidatePlugin`) に関連する 2 件のバグ修正を含むパッチリリースです。Node.js 22.x 以外の環境で `aws-cdk-lib` のインストールが `EBADENGINE` で失敗する問題と、`CDK_VALIDATION=false` を設定しても組み込みバリデーションが無効化されない問題が修正されています。

**リリース:** [v2.262.1](https://github.com/aws/aws-cdk/releases/tag/v2.262.1)

---

## バグ修正

### `core`: Node.js 22.x 以外で `aws-cdk-lib` のインストールが失敗する問題を修正 ([#38382](https://github.com/aws/aws-cdk/pull/38382))

**修正内容:**

- v2.262.0 で同梱された `@aws/cloudformation-validate@1.5.0-beta` が `engines.node` を `^22.15.0` (`>=22.15.0 <23.0.0`) にピン留めしていたため、Node.js 20 / 21 / 23 / 24 系の環境で `aws-cdk-lib` のインストールが `EBADENGINE` で拒否されていました。
- これは `aws-cdk-lib` 本体の `engines.node: ">=20.0.0"` とも矛盾しており、Yarn Classic ユーザー、および `engine-strict` を有効化している npm / pnpm ユーザーでインストールが完全に失敗していました。

**影響を受けていた状況:**

- Node.js 20.x / 21.x / 23.x / 24.x 環境での `aws-cdk-lib@2.262.0` インストール。
- Yarn Classic (エンジンチェックが厳格) 、および `engine-strict=true` 設定の npm / pnpm。

**修正後の状態:**

- 同梱パッケージが `@aws/cloudformation-validate@1.5.1-beta` へバンプされ、`engines.node` が `>=20.0.0` に広がりました。npm のエンジン制約も削除されています。
- Node.js 20.0.0 / 24.16.0 の各バージョンで、npm (デフォルト + `engine-strict`) 、pnpm (デフォルト + `engine-strict`) 、Yarn Classic 全てのケースでインストール可能であることが検証されています。

**ポイント:**

- コード変更はなく、依存関係のバージョンバンプのみで解決されています。`aws-cdk-lib` の API に影響はありません。
- v2.262.0 で `EBADENGINE` に遭遇していた場合は、v2.262.1 にアップグレードするだけで解決します。

### `core`: `CDK_VALIDATION=false` が組み込みテンプレート検証を無効化しない問題を修正 ([#38379](https://github.com/aws/aws-cdk/pull/38379))

**修正内容:**

- v2.262.0 で追加された組み込み `CloudFormationValidatePlugin` が `app.synth()` 内で常に無条件に実行されていたため、`cdk synth --no-validation` や `CDK_VALIDATION=false` 環境変数の指定に関係なく検証が走り、診断結果が出力される問題を修正しました。
- 「CloudFormation Validate」と名乗るサブシステムが、ユーザーが明示的に検証を無効にしても動作し続けるという意味論的な矛盾が解消されます。

**修正内容の詳細:**

- `core/lib/private/synthesis-validation.ts` の `pluginsToEvaluate()` が、`CDK_VALIDATION` 環境変数が `'false'` に設定されている場合には組み込みの `CloudFormationValidatePlugin` シングルトンを自動登録しないように変更されました。
- CLI の `--no-validation` オプションが利用する環境変数と統一されたことで、検証レイヤーが一貫した制御下に置かれます。
- ユーザーが明示的に `Validations.of(app).addPlugins()` や `policyValidationBeta1` で登録したバリデーションプラグインは、明示的なオプトインとして扱われ、`CDK_VALIDATION=false` の影響を **受けません** (引き続き実行されます) 。
- 制御ロジックはフレームワーク側 (CLI ではなく `core`) にあるため、`Template.fromStack()` を使ったユニットテストなどの非 CLI 合成パスもカバーされます。

**使用例:**

```bash
# 組み込み CloudFormation Validate をオフにして CDK app を実行
export CDK_VALIDATION=false
cdk synth
```

```typescript
// ユーザーが明示的に登録した検証プラグインは CDK_VALIDATION=false でも動作し続ける
import * as cdk from 'aws-cdk-lib';

cdk.Validations.of(app).addPlugins(
  // このプラグインは明示的なオプトインなので、CDK_VALIDATION=false でも実行される
  new cdk.CloudFormationValidatePlugin({
    guardRules: ['path/to/my/rules.guard'],
  }),
);
```

**ポイント:**

- `CDK_VALIDATION` に `false` を設定できるのは、あくまで CDK が **自動的に登録した** 組み込み検証エンジンだけです。ユーザーが `Validations.of(app).addPlugins()` で登録したものは影響を受けません。
- 現時点で `cdk synth --no-validation` は CLI から app プロセスへ `CDK_VALIDATION` 環境変数を転送しないため、CLI フラグ経由で組み込み検証を完全に無効化するには追随する CLI 側の変更が必要です (aws/aws-cdk-cli#1751 で追跡中) 。当面は `CDK_VALIDATION=false` を環境変数として明示的にセットしてください。
- `Template.fromStack()` を使ったユニットテストでも同一フラグが有効です。CI 環境で不要な検証を切りたい場合に活用できます。

## まとめ

v2.262.0 で導入された組み込み CloudFormation 検証プラグインに関連する 2 件のバグを修正するパッチリリースです。Node.js 22.x 以外を利用している場合や、`CDK_VALIDATION=false` で組み込み検証を無効化したいユースケースでは、v2.262.1 へのアップグレードを推奨します。
